# 生成 PRD-lite（第 2 步）

## 目标
用最小篇幅冻结「这次做什么」，后续写码与复核都以它为准。

## 字段
- `what`：一句话说明要做什么。
- `how`：技术路径，结合工程现状，不写代码。
- `done`：1～5 条可验收标准，必须能被第 6 步机器验证或第 7 步人审判断。
- `non_goals`：明确不做什么，防止顺手重构。
- `scope`：涉及的页面/模块/接口。
- `change_limit`：预计最多改多少个文件，默认 12。

## 原则
- 严格依据用户原话，不发明用户没点名的页面、菜单或报表。
- 模型不可用时退化为保守 PRD，并在事件里标注「已降级」。
- 每次重跑版本号 `rev` 递增，旧版本不覆盖语义，只冻结新版本。
