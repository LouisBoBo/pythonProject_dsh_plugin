# 远端 Webhook 自动审码 · 新用户使用手册

> 插件：`@zhongruan/dsh-remote-review`  
> 设置入口：**设置 → 远端审码**  
> 目标：照着做，就能从「提交/推送」一路走到「飞书里看到审码报告」。  
> 更细的运维/排障总册见：[remote-review-远端Webhook审码-完整实施方案.md](./remote-review-远端Webhook审码-完整实施方案.md)

---

## 0. 一分钟搞清它是干什么的

| 你做了什么 | 插件做什么 |
| --- | --- |
| 在业务仓 `git commit`（装了提交 Hook） | 本机 Webhook 收到通知 → 调审码引擎 → 报告写到飞书 |
| 或向 GitHub/GitLab `git push`（配了仓库 Webhook） | 同上（适合公司服务器那一套） |

**重要：**

- 审码「判题」仍由 **WorkBuddy 审码引擎**完成；本插件负责 **触发、拉仓/准备目录、投递飞书**。
- 飞书 App Secret、Webhook 密钥等 **只存在本机** `~/.zhongruan/remote-review/config.json`，**不要**写进业务 git。

---

## 1. 安装插件（第一次）

1. 打开 **WorkBuddy / DSH 聊天壳**。
2. 进入 **设置 → 插件市场**。
3. 安装 **`@zhongruan/dsh-remote-review`**。
4. 在「已安装」里确认状态为 **已启用 / 运行中**。
5. **完全退出并重新打开** WorkBuddy（装完/升级后务必重启，否则设置页可能不出现）。
6. 打开 **设置**，左侧应能看到 **`远端审码`**。

自检：浏览器或本机访问  
`http://127.0.0.1:18787/health`  
应返回服务在线（默认端口 **18787**）。

---

## 2. 设置页怎么填（照抄顺序）

打开 **设置 → 远端审码**。

### 2.1 顶部：连哪台服务

日常本机自用：

| 项 | 填什么 |
| --- | --- |
| 服务 host | `127.0.0.1` |
| port | `18787` |
| 路径前缀 | **空** |

点 **`连接并加载`**。

若连公司已部署的审码机：可点 **`填公司服务器`**（会带上公司 host / 前缀），再 **`连接并加载`**。  
注意提示：**不要把公网地址填进下面的「引擎/监听」**；引擎一般填那台机器自己的本机地址。

### 2.2 「1 · 审码引擎」

| 项 | 本机常见值 |
| --- | --- |
| WorkBuddy 引擎地址 | `http://127.0.0.1:8000`（以你环境实际端口为准） |

先保证审码引擎本身能打开、能审；引擎挂了则 Webhook 能收单但审码会失败。

### 2.3 「2 · 飞书文档」

| 项 | 说明 |
| --- | --- |
| 飞书 App ID | 开放平台应用 ID |
| 飞书 App Secret | 应用密钥（保存后界面可能显示「已保存」） |
| 文档库 space_id（推荐） | **一串数字**，不是浏览器 URL 里 `/wiki/` 后面那串 |
| 文档库父节点（可选） | URL 里 `/wiki/` 后面的 token；空则落在文档库根 |
| 云盘文件夹 Token | **一般留空**（个人云盘常权限不够） |

飞书侧务必：

1. 把应用 **添加到目标文档库**，权限可编辑。  
2. 开通并发布含 **`docx:document.block:convert`（转换文本为云文档块）** 的版本。  
3. 缺 convert 权限时，报告容易变成「白茫茫纯文本」或投递失败。

### 2.4 「3 · Webhook 服务」

| 项 | 建议 |
| --- | --- |
| 监听地址 | `127.0.0.1`（本机） |
| 端口 | `18787` |
| Webhook 密钥 | 本机自测可空；公网/公司机建议配置 |

保存后页面会提示类似：

- Webhook 地址：`http://127.0.0.1:18787/webhook`
- 配置目录：`~/.zhongruan/remote-review/`

### 2.5 保存与检测

1. 点 **`保存配置`**（写入本机 config，不进业务仓）。  
2. 若改过端口/监听：**重启插件/宿主** 后再用。  
3. 点 **`检测服务`**，期望看到服务在线、飞书已配置、引擎就绪一类提示。

## 3. 两条使用路径（选一条就会）

### 路径 A：本机提交就审（适合个人开发机）

1. 在设置 **「4 · 给业务仓库装提交触发」** 填业务仓**绝对路径**，例如：  
   `/Users/你/Desktop/某业务项目`
2. 点 **`安装提交 Hook`**。  
   - 会写 `.git/hooks/post-commit`（标记由本插件管理）。  
   - 若已有旧 Hook，会改名备份并链式调用，一般不踩掉原逻辑。  
   - **不会**把飞书密钥写进仓库。
3. 在该仓库正常改代码 → `git commit`。  
4. Hook 在后台 `curl` 敲门到本机 Webhook（**不阻塞**你的提交）。  
5. 等一两分钟，用下面「看结果」的方法查飞书链接。

> 只 commit、从不 push：本机 Hook 路径仍然有效。  
> GitHub/GitLab 上的「仓库 Webhook」则要靠 **push** 才会打到远端。

### 路径 B：推到 GitHub/GitLab 再审（适合公司机）

1. 公司机已部署本插件 + 引擎 + 飞书（运维按完整实施方案做）。  
2. 在 Git 平台仓库设置里添加 Webhook：  
   - URL：公司提供的 `…/webhook`  
   - Secret：与设置页「Webhook 密钥」一致（若启用）  
3. 开发者照常 `git push`。  
4. 平台 POST → 插件拉仓 → 审码 → 飞书。

## 4. 怎么看结果（新用户最常用）

### 4.1 对话里问助手（有工具时）

可让助手调用（名称以实际工具为准）：

| 目的 | 工具意向 |
| --- | --- |
| 服务是否正常 | `remote_review_status` |
| 最近任务列表 | `remote_review_jobs` |
| 飞书失败重试 | `remote_review_retry_feishu`（传入 `rr-…` 任务 id） |
| 不提交先试一条 | `remote_review_simulate` |

### 4.2 浏览器 / 接口

- 任务列表：`http://127.0.0.1:18787/jobs`  
- 若配置了密钥，请求头带：`X-Remote-Review-Secret: <密钥>`  
- 飞书失败可：`POST …/jobs/<id>/retry-feishu`

成功时详情里一般有飞书文档链接（`feishu.cn/wiki/…` 等）。

### 4.3 飞书没配好时

报告可能先落在本机：

`~/.zhongruan/remote-review/feishu-out/`

配好飞书后对失败任务执行「重试飞书」即可。

## 5. 验收清单（第一次建议全勾）

- [ ] 设置页能打开「远端审码」  
- [ ] `http://127.0.0.1:18787/health` 正常  
- [ ] 引擎地址能访问  
- [ ] 飞书 App 已进文档库且 convert 权限已发布  
- [ ] 本机路径 A：装 Hook → commit → `jobs` 出现新任务  
- [ ] 任务最终可打开飞书报告（或 `feishu-out` 有备份）

## 6. 常见问题（照着对号）

| 现象 | 先查什么 |
| --- | --- |
| 设置里没有「远端审码」 | 插件是否启用；是否已**重启** WorkBuddy |
| commit 了没任务 | Hook 是否装在**正确仓库根**；服务是否在线；90 秒内同 commit 可能去重跳过 |
| 有任务但审码失败 | 引擎是否启动；引擎地址是否填成了公网 IP |
| 飞书打不开 / 白板 | space_id 是否填错成 wiki token；缺 convert 权限；应用未发布；未添加到文档库 |
| 端口异常 / 设置加载失败 | 是否残留旧进程占 18787；结束占用后重开 WorkBuddy |
| 改了端口不生效 | 保存后需重启服务/宿主 |

---

## 7. 安全与边界（请记住）

- 密钥只放本机配置 / 设置页，**禁止**进业务仓库与插件源码。  
- 本插件不替代审码规则引擎，只做触发与投递。  
- 默认只监听本机；对公网暴露必须配密钥并按公司网络规范加固。
