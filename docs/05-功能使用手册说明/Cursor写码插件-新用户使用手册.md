# Cursor 写码插件 · 新用户使用手册

> 插件：`@zhongruan/dsh-cursor-coding`  
> 设置入口：**设置 → Cursor 写码**  
> 目标：照着做，就能在 DSH 聊天里完成「澄清 → 确认 → 沙箱写码 → 同步 → 正文结论」。  
> 主流程冻结说明：[Cursor写码插件-主流程冻结.md](./Cursor写码插件-主流程冻结.md)  
> 会话分层（聊天认 DSH、执行认本机 Job）：[DSH会话与记忆分层.md](../架构与选型/DSH会话与记忆分层.md)

---

## 0. 一分钟搞清它是干什么的

在聊天里描述要改的功能后，插件会：

1. （大改时）用 DSH 原生选择题帮你把需求问清  
2. 弹出 **确认卡**，你点了才开工  
3. 在本机 **沙箱**里用 **Cursor Local** 摸清项目再改代码（不是直接乱改宿主机）  
4. 按可写范围同步回你的工程  
5. 把 **本轮结论**写进聊天正文，方便下一轮继续说

| 层 | 谁管 | 你要关心吗 |
| --- | --- | --- |
| 聊天记录 / 结论 | DSH 会话 | 刷新后聊天还在 |
| 写码过程 / 沙箱 | 本机 Job（`ccj-…`） | 进度卡可看过程 |
| 浏览器缓存 | 仅加速 | 关标签可丢，不影响对错 |

---

## 1. 安装与首次配置

### 1.1 安装

1. 打开 WorkBuddy / DSH。  
2. **设置 → 插件市场** → 安装 **`@zhongruan/dsh-cursor-coding`**。  
3. 确认 **已启用 / 运行中**。  
4. **重启**聊天壳（或按公司脚本 `link` / `restart-web` 后硬刷新页面）。  
5. **设置**左侧应出现 **`Cursor 写码`**。

开发机联调可用：`dsh plugin --profile web add ./dsh-cursor-coding`（只会出现在「已安装 / 本地开发」，不会进「发现」）。正式给别人用必须 `./scripts/internal-market/pack.sh dsh-cursor-coding` 再 `upload.sh`。

### 1.2 必填：Cursor API Key

打开 **设置 → Cursor 写码**：

1. 在 **「1 · Cursor API Key（硬性）」** 粘贴你的 Cursor API Key。  
2. 点 **`保存配置`**。  
3. 密钥只存本机：  
   `~/.zhongruan/cursor-coding/config.json`（权限 600），**不会**进业务 git。  
4. 点 **`检测服务`**，确认服务在线且 Key 已配置。

默认本机服务：`http://127.0.0.1:18788`。

> 未填 Key 时工具会提示：请先到「设置 → Cursor 写码」填写 Cursor API Key。  
> 正式使用请填真实 Key；`test-` 开头的假 Key 在非 Mock 模式下会被拒绝。

### 1.3 建议填写：可写范围

在 **「2 · 本机服务」**：

| 项 | 建议 |
| --- | --- |
| 监听端口 | 默认 `18788`，冲突再改 |
| 默认可写范围 | 每行一个相对前缀，如 `src/`、`frontend/src/`；FastAPI 务必加上 `backend/app/schemas.py`（及 `models.py`），否则易出现「路由已改、schema 未同步 → 请求失败」 |

范围越准，越不容易改飞。只改某个目录时务必写上前缀。

改端口后需 **重启插件/宿主** 再生效。

## 2. 开聊前准备（30 秒）

1. 侧栏 **打开/绑定**要改的工程目录（会话工作区）。  
2. **新开一轮对话**（大改建议，避免旧上下文干扰）。  
3. 浏览器对聊天页 **硬刷新**一次（装插件或升级后尤其重要）。  
4. 用一句话说清诉求，例如：  
   - 小改：`把登录按钮字号调大一点`  
   - 大改：`MES 报表中心新增员工工时报表，要筛选和导出`

---

## 3. 标准使用流程（照着点）

### 步骤 1：说需求（大改会先澄清）

对助手直接说你的目标。

若是 **新增 / 删除报表·页面·菜单 / 大改**，助手应先调用 DSH 原生 **`ask_user_question`**（选择题卡）：

1. 你勾选选项并提交。  
2. 不要自己长文反复解释代替选项卡。  
3. 提交后才会进入写码确认。

小改（改文案、改样式、修小 bug 等）可能跳过澄清，但仍会有确认卡。

### 步骤 2：确认卡 — 必须你点才写码

卡片标题类似：**「Cursor 写码 · 确认」**（续改时为 **「Cursor 写码 · 续改」**）。

你会看到：

- **工作区（当前会话）**：来自侧栏绑定目录  
- **写码诉求（你的原话）**  
- 按钮：**`确认并用 Cursor 开写`**

**点确认之前：**

- 不会改你的工程  
- 不要催助手「再输出一段方案」  
- 聊天正文应保持干净（过程不进正文）

点 **`确认并用 Cursor 开写`** 后才真正开工。

若按钮灰掉 / 诉求为空：先确认侧栏有工程，或硬刷新后再试。

### 步骤 3：进度卡 — 只看过程

标题变为：**「Cursor 写码 · 进度」**。

卡上可能出现：

- `写码中` / `自动同步中` / `已完成`  
- 思考、读文件、搜索、修改等工具过程  
- 「正在自动同步并刷新前端…」等提示  

说明：

- **本卡只展示过程（思考/工具）**  
- **完整结论在对话正文**，不在卡里重复贴一大段方案  

Cursor 会在 **沙箱**里先摸清技术栈与目录（读 `package.json` 等），再按现有架构修改；不是聊天 Agent 直接改宿主机。

### 步骤 4：正文结论

写码与同步结束后，聊天正文必须出现以 **`## 本轮结论`** 开头的内容（**凡写码含续改都要有**；由 begin/continue 收口带回，不必再等 Agent 调 finish）。一般包括：

- 做了什么  
- 改了哪些文件  
- 如何验收  
- 若要继续改，可直接在对话框说下一句  

进度卡底部可能提示：过程已结束，请向下查看正文结论。若卡显示 FINISHED 但正文没有结论，即视为缺陷。

## 4. 续改（同一对话里接着改）

当结论出来后，你可以直接说：

- `按钮再大一点`  
- `筛选加上日期范围`  
- `刚才那个菜单文案改一下`

助手应走 **续改**（确认卡 → 进度 → 结论），并尽量复用本会话上次成功任务与沙箱。

**分流（由助手识别真实意图，不靠关键词表）**

| 意图 | 怎么走 |
| --- | --- |
| 已够落码（修问题、改一处、加列等） | **直接**确认卡开写 |
| 大范围新功能 / 删菜单页 / 选项未定 | 先选择题澄清，再确认卡 |

注意：续改认的是 **当前 DSH 会话**，不是「同目录最新任意任务」。

---

## 5. 沙箱与同步（安全相关，建议读懂）

```text
你的真工程 ──拷贝/稀疏准备──► 本机沙箱
                                │
                         Cursor 在这里改
                                │
                         校验可写范围
                                ▼
                         同步回真工程（默认自动）
```

- 沙箱目录在：`~/.zhongruan/cursor-coding/sandboxes/`  
- 任务账本在：`~/.zhongruan/cursor-coding/jobs/`  
- **默认可写范围外的改动不会偷偷整仓覆盖**  
- 例外（防半套契约）：配置里若含 `…/routers/`，插件会**自动连带**同包 `schemas.py` / `models.py` 等；审后若 routers 已改而 schema 在范围外，会**提升进同步**，避免「写入成功却请求失败」  
- 默认 **自动同步**到真工程；若环境关闭了自动同步，进度卡会出现勾选文件 + **`同步到本机`**

运维可选环境变量（一般用户不用改）：

| 变量 | 作用 |
| --- | --- |
| `CURSOR_CODING_AUTO_APPLY=0` | 关闭自动同步，改为卡上手工同步 |
| `CURSOR_CODING_MOCK=1` | 仅自检/联调 Mock，不要当正式写码 |

## 7. 验收清单（第一次建议全勾）

- [ ] 设置里有「Cursor 写码」，Key 已保存，检测服务通过  
- [ ] 侧栏已绑定工程  
- [ ] 说一句小改需求 → 出现确认卡 → 点确认 → 出现进度卡  
- [ ] 进度中能看到读文件/搜索等「摸底」再改动  
- [ ] 结束后正文有「本轮结论」，真工程文件有预期变更  
- [ ] 再说一句续改，仍走确认卡且不串到别的会话任务

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 提示未配置 API Key | 设置 → Cursor 写码 → 保存 Key → 检测服务 |
| 没有确认卡 / 界面像旧版 | 硬刷新；确认插件已升级并重启宿主 |
| 确认卡诉求为空 | 侧栏是否有工作区；硬刷新；让助手带上你的原话再 begin |
| 进度一直转、结论不来 | 看卡上是否失败；设置页用 job_id 回看；再调一次收结论 |
| 刷新后进度卡状态乱 | 以任务 id 为准；已完成应显示已完成（勿强行再点确认） |
| 刷新后页面被拽到最底部 | 已修复：整页滚动仅在本页点过「确认并用 Cursor 开写」后才允许；刷新恢复禁止抢滚动。请硬刷新加载最新客户端 |
| 改错目录 / 改太多 | 收紧「默认可写范围」；大改先走澄清选项 |
| 端口被占用 | 改设置端口，或结束占用 18788 的非本插件进程 |
| 想看是否沙箱 | 进度里有「沙箱就绪」；磁盘可见 `…/sandboxes/ccj-…` |

## 9. 和助手怎么配合（省事口令）

你可以这样说：

- 开工：`请按写码流程：先澄清（如需），再确认卡，最后给本轮结论。`  
- 续改：`在上一轮基础上继续：……`  
- 不要：`你先用终端把整个仓库 ls/grep 一遍再写`（这应由 Cursor 在沙箱内做，聊天侧不要扫仓代写）
