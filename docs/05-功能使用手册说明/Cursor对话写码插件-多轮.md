# Cursor 对话写码插件 · 功能与使用手册

> **现行交付**：`@zhongruan/dsh-cursor-chat` **0.3.70**  
> 设置入口：**设置 → Cursor 对话写码**  
> 市场安装后自行点「更新」；开发联调勿当正式交付。  
> 旧包 `@zhongruan/dsh-cursor-coding` 仍可并存，**新产品能力以本文为准**。

## 1. 一分钟定位

在 DSH / WorkBuddy **聊天**里像跟 Cursor 对话一样改任意本机工程：

1. 说清诉求（可贴图）；大改 / 增删页面菜单会先澄清。  
2. **确认卡**点确认后才开工（确认前不改真工程）。  
3. **写码**在本机沙箱里由 Cursor Local 改盘，再按**项目画像自动可写范围**（或显式硬配置）同步回真工程。  
4. **运维**（重启、测、日志等）不进沙箱，在真实工程终端处理。  
5. 同步后跑 **交付审计**；能修的问题自动续修再验，不把接口 422 / 缺列 500 假绿留给你。  
6. 聊天正文给 **本轮结论**；结论下可点「已编辑 N 个文件」在右侧工作区打开。

| 层 | 谁管 | 说明 |
| --- | --- | --- |
| 聊天 / 结论 | DSH 会话 | 刷新后对话还在 |
| 写码 / 运维过程 | 本机 Job（`cch-…`） | 进度卡 SSE |
| 配置 Key / 端口 | 插件设置页 → `~/.zhongruan/cursor-chat/` | 不进业务 git |
| MES / LLM 等业务凭证 | WorkBuddy **系统配置** | 插件不另要一套 |

## 2. 功能总览（现行全部能力）

### 2.1 写码主路径

| 能力 | 说明 |
| --- | --- |
| 任意本地工程 | 以侧栏当前工作区为准，不绑死某一业务仓 / 技术栈 |
| 澄清 → 确认 → 进度 → 结论 | 大改 / 增删页菜单先选择题；确认前不写盘（HITL nonce） |
| 沙箱改盘 + 自动同步 | Cursor 只改沙箱；按写范围校验后默认同步回真工程 |
| 多轮续改 | `zr_cchat_continue`，同会话优先 `Agent.resume` |
| 贴图多模态 | begin/continue 传 `images`（路径 / base64 / url）进 Cursor |
| 删除页面 / 菜单 / 功能 | 先澄清；删除验尸走项目画像探针，禁止写死顶层路径误杀 |
| 可写范围（自动） | **默认按项目画像**：嵌套前后端 → `auto`；仓根 Vite/FastAPI 或认不出 → `open`；显式 `writeScope` → `config` 硬闸。用户一般不用配 |
| 契约连带 / 软放行 | routers 可连带 schemas/models；`auto` 下范围外但仍可交付的文件软放行，避免挡真写码 |
| 敏感拦截提示 | `.env` 等可写在沙箱，**不同步真工程**；结论标明「安全拦截（仅沙箱、未同步真工程）」 |

### 2.2 运维终端（不进写码沙箱）

| 细类 | 典型说法 | 行为 |
| --- | --- | --- |
| 启动 / 重启 | 「把项目跑起来」「重启前后端」 | **优先**读项目自己的命令后台拉起并验端口；认不出再降级 Cursor SDK |
| 跑测试 | 「跑一下单测」 | 真实工程终端，Cursor SDK |
| 装依赖 | 「装一下依赖」 | 真实工程终端 |
| 看日志 | 「看后端报错日志」 | 真实工程 / `.dev-logs` |
| 查环境 | 「Python / Node 版本」 | 真实工程终端 |
| 排障 | 「接口 500 帮看一下」 | 真实工程终端；**带改码的句子仍走写码沙箱** |

重启细则见：[重启服务方案.md](../04-Cursor-AI-Coding逼真版本/重启服务方案.md)。

### 2.3 Git 交付出口（按需，不强制）

平时改码只同步到工作区，**不会**自动 `commit` / 开 PR。  
仅当你明确说「提交代码 / commit / 开 PR / 提 MR / 推上去让人审」时，助手调用 `zr_cchat_git_deliver`：

1. 读当前工作区未提交改动（可跨多轮写码）。  
2. 出确认卡：**默认展示当前仓库地址与当前分支**；可改提交分支、PR 基线、说明；勾选文件（`.env` 等敏感默认排除且禁止提交）。  
3. 你点「确认提交并开 PR」后才：建/切分支 → `commit` → `push` → 尽量用本机 `gh` 开 PR（未登录则只 push，结论提示手动开 PR）。  
4. 失败结论写清停在哪一步（分支 / 提交 / 推送 / 开 PR）。

详细口径见：[写码插件-Git交付出口方案.md](../04-Cursor-AI-Coding逼真版本/写码插件-Git交付出口方案.md)。

### 2.4 交付审计与自动续修

同步后（及沙箱预审计）按本轮改动跑检查。**结果只认落盘与检查字段**，不用用户正文猜「取消 / 成功」。

| 检查项 | 做什么 | 失败时 |
| --- | --- | --- |
| `synced_bytes` | 声称同步的文件在真工程有内容 | **挡交付**（落盘硬闸） |
| `delete_target` | 删除目标是否真的去掉 | **挡交付** |
| `api_mount` | 新增 API 是否挂到 FastAPI 路由 | **可续修** → 自动再改再验 |
| `param_contract` | 前端 `page_size` 是否超过后端最严 `le` | **可续修**（用 `min(le)`，禁止用 max 假通过） |
| `schema_drift` | ORM 声明列是否在本机 `.db` 表里存在 | **可续修**；同步了模型却找不到 `.db` **失败**（禁止静默通过） |
| `menu` / `requirement_page` | 菜单 / 页面接线是否落地 | **可续修** |
| `delete_claim` 等 | 删除声称与验尸 | 见删除车道 |

结论里独立展示 `审计：✅/❌`；可修项未过关**不得**标「已完成」。

### 2.5 项目画像（灵活布局）

`projectLayout` 是**唯一**布局入口：自动认嵌套前后端根、Vite / FastAPI、端口、菜单与挂载探针。  
禁止再写死 `frontend/src/layouts/AppLayout.vue` 一类顶层路径；同仓备份目录不会误杀本轮工程。

### 2.5 进度卡与交互

| 能力 | 说明 |
| --- | --- |
| 流式过程 | 思考 / 读文件 / Shell / 改文件跟手展示 |
| 用户选择题 | Cursor 调 `ask_user_choice` → 进度卡选项；提交走 HITL nonce，只认完整选项 |
| 「已编辑 N 个文件」 | 结论下改动卡（兜底对齐底座原生卡）；点击行在右侧工作区打开 |
| 取消 | 进行中可取消；已成功 / 失败终态不污染业务结果，取消结论不写「请你验收」 |
| 重启按钮 | 进度卡可触发按项目命令重启后端等（带 HITL） |

### 2.6 安全与防污染

| 项 | 规则 |
| --- | --- |
| 确认 / 取消 / 用户选择 | 一律 HITL nonce；禁止裸 POST 伪造 |
| 路径 | 相对路径拒绝 `..` / 盘符 / `~`（画像与打开工作区一致） |
| Mock | 仅 `CURSOR_CHAT_MOCK=1` **且** `CURSOR_CHAT_SELFTEST=1` 允许假写码；继承来的 MOCK 会被剥掉，禁止写进 `.cursor-chat-mock.md` 冒充交付 |
| 空 Key | 正式模式拒绝静默 Mock |
| 控制信号 | 取消 / 终态只认权威字段（`error.code`、Job `status`），禁止扫正文「取消」 |

### 2.7 边界（不归本插件）

- MES 查数、售后、测试用例等已命中 **ESC** 技能 → 走 ESC，不抢 `zr_cchat_*`  
- 用量统计 / Key 限额 → `dsh-key-quota`  
- 知识库、自动化、远端审码 → 各独立插件  
- 产品壳改动 → 只改 `DSH_MOM` 的 `desktop/shell`（与本插件无关）

## 3. 安装与首次配置

### 3.1 安装

1. **设置 → 插件市场 → 发现**，安装 / 更新 **`@zhongruan/dsh-cursor-chat`**（当前市场 latest：**0.3.70**）。  
2. 确认已启用。  
3. **完全退出**安装版客户端再开（不要用源码桌面验收）。  
4. 设置左侧出现 **「Cursor 对话写码」**。

开发机：`dsh plugin add ./plugins/dsh-cursor-chat` 只用于联调，**不会**出现在发现列表。上架必须 `pack.sh` + `upload.sh`。

### 3.2 必填：Cursor API Key

**设置 → Cursor 对话写码**：

1. 粘贴 Cursor API Key → **保存配置**。  
2. 密钥落本机：`~/.zhongruan/cursor-chat/config.json`（勿进业务 git）。  
3. **检测服务**：默认 `http://127.0.0.1:18791`。

### 3.3 可写范围（默认自动，一般不用配）

> **2026-11-16 已在本机验收**：嵌套仓 `auto`、仅开 `frontend` 子目录 `open`、敏感 `.env` 拦截与结论提示、显式 `writeScope` 硬闸。

开工时按**当前侧栏工作区**的项目画像决定范围（用户不必理解 `write_scope`）：

| `write_scope_source` | 何时 | 行为 |
| --- | --- | --- |
| `auto` | 认出嵌套前后端根（如 `frontend/`+`backend/`、`apps/web/`+`apps/api/`） | 用这些前缀做沙箱/初筛；进度可提示「可写范围（项目画像）：…」 |
| `open` | 仓根就是 Vite/FastAPI，或认不出布局 | 整仓不收窄（`write_scope` 为空） |
| `config` | 本机 `config.json` 显式写了非空 `writeScope` | **硬边界**；范围外变更不默认同步；结论写「硬配置拦截，未同步」（不是空跑） |

补充规则：

- **`auto` 软放行**：范围外但仍可交付的文件（如根目录 `README.md`、`docker-compose.yml`、docs）仍可同步，避免挡真写码。  
- **敏感硬拒**：`.env`、密钥、本机 `.db` 等任何 source 都不进真工程；若沙箱写过，结论有「安全拦截（仅沙箱、未同步真工程）」，请以真工程为准验收。  
- **契约连带**：改 routers 时可自动带上 schemas/models。  
- **高级覆盖**：设置页**没有**可写范围填空框；仅当需要硬闸时编辑 `%USERPROFILE%\.zhongruan\cursor-chat\config.json` 的 `writeScope`（测完请改回 `[]`）。

## 4. 标准写码流程

1. 侧栏打开要改的工程；新开对话（大改建议）。  
2. 一句话说清目标；可贴界面截图。  
3. 需要时先答澄清题 → 出现 **确认卡** → 点确认。  
4. 看 **进度卡**（过程）；不要指望卡里贴完整方案。  
5. 正文出现本轮结论；下方可点改动文件在右侧预览。  
6. 同一会话继续说下一句 → **续改**（仍走确认 → 进度 → 结论）。

口令示例：

- `请按写码流程：先澄清（如需），再确认卡，最后给本轮结论。`  
- `在上一轮基础上继续：筛选加上日期。`  
- `删除物料入库功能`（走删除车道 + 删除审计）

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 未配置 API Key | 设置 → Cursor 对话写码 → 保存 → 检测服务 |
| 没有确认卡 / 像旧版 | 确认装的是 **cursor-chat**；硬刷新；完全退出再开 |
| 接口 422 page_size | 审计应拦住并续修；仍出现则更新到 0.3.70+ 并重跑一轮 |
| 接口 500 缺列 | `schema_drift` 应续修迁移；确认本机有对应 `.db` |
| 删除已成功却报未删 | 旧版探针写死路径；0.3.63+ 走项目画像，请更新 |
| 改动卡点不开 | 需有 sessionId；更新后完全退出再开 |
| 写成了 mock 说明文件 | 检查环境是否误带 `CURSOR_CHAT_MOCK`；正式模式已禁止 |
| 端口占用 | 改设置端口或结束占用 18791 的进程 |
