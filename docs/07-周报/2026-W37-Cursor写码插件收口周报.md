## 二、本周完成工作

### 1. 写码主流程收口并冻结

- 固化四步：**澄清 → 确认卡 → 进度卡 → 聊天正文结论**（续改同路径，凡写码必有结论）。
- 入口级新增/删除（报表·页面·菜单）强制澄清；小改可直接确认开写。
- 联调复盘已归档：写码 / 删码 / 续改弯路与定稿决策可追溯。

### 2. 进度过程体验提升（后冻结）

- 进度卡加厚：思考流、工具行、过程说明、编辑短片断等，整体观感明显好于早期「只有状态行」。
- 对照 Cursor IDE 原生输出写了完整对比报告：**内容同源高、过程约 7/10、工具参数/结果偏薄**。
- 评估后再补 pattern/command 映射：**现网流常无对应字段，加了几乎无观感收益 → 按产品决策停做**。
- 修复进度卡内「说明方案 / 结论」重复刷出，结论仍只落在聊天正文。

### 3. 插件韧性三项（本周后半）

| 能力 | 落地情况 |
| --- | --- |
| 装失败自动回退旧版 | 公司市场强制安装脚本：先备份再替换，失败自动还原 |
| 四套软件兼容声明 | WorkBuddy / DSH 运行时 / 写码插件 / Cursor SDK；`/health` 上报，不阻断写码 |
| 服务崩了少拖垮聊天 | 写码 HTTP 默认独立子进程，失败可回退同进程；确认票据已落盘跨进程共用 |

> 说明：页面内前端脚本仍随宿主加载，无法做到「任意插件故障绝对不影响聊天」；隔离边界已在文档写清。

### 4. 文档与口径

- 主流程冻结说明、输出 VS 原生对比报告、韧性说明、写码/删码/续改复盘。
- 对外建议口径：「DSH 确认后由 Cursor 改码，进度跟手、正文有结论」；**不承诺与 IDE 对话框 1:1**。
