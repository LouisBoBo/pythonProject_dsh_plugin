## 一、本周目标（一句话）

把上周收口成果**稳住、验实、按需上架**；写码侧不扩需求，审码与文档按专题推进；重大产品口径待领导拍板后再动。

## 二、优先级与任务

| 优先级 | 事项 | 做什么 | 产出 / 验收 | 备注 |
| --- | --- | --- | --- | --- |
| **P0** | 写码稳定性回归 | 真实工程多轮：小改 / 删菜单·页面 / 续改；盯进度卡是否再刷结论、子进程隔离、确认→正文结论 | 问题清单（有则修 bug，无则记「观察通过」） | 不改四步形态 |
| **P0** | 版本落地确认 | 开发机 `pnpm build` + 彻底重启宿主；核对 `/health`：`pluginVersion≥0.6.43`、`compat`、`serverMode` | 本机健康检查通过截图或记录 | 装盘用带回退脚本 |
| **P1** | 市场发布（可选） | 若领导要求本周上架：打包 → 上传公司市场 → 用 `install-latest` 验证回退路径 | 市场可见版本 + 安装验证记录 | **待拍板上线节奏** |
| **P1** | 审码专题推进 | 远端 Webhook / 飞书文档链按既有方案补齐或排障（非写码主线） | 专题进展备注 | 与写码并行、互不搅 |
| **P2** | 文档与口径 | 按需补使用向说明；周会用「七成接近 + 门禁」口径，避免承诺 IDE 1:1 | 口径一致 | 对照报告已有 |
| **P2** | 宿主版本声明（预研） | 评估 WorkBuddy 写入 `WORKBUDDY_VERSION` / `DSH_APP_VERSION` 的可行性 | 半页方案或结论「需宿主排期」 | 不单方面硬拦写码 |
