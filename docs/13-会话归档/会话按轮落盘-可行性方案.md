# 会话按轮落盘：可行性方案

> **状态**：P0 已按默认项实施（2026-10-27）。桌面宿主有 `agent/turn-stopping`（serial），派发时由 `agentEvents` 把 `agent` 注入 payload。  
> **日期**：2026-10-27  
> **落点**：本仓库独立 DSH Bundle `@zhongruan/dsh-transcript`（目录 `plugins/dsh-transcript/`）  
> **交付形态**：公司插件市场安装。开发机可以本地 link 联调，发现页看不到本地 link。  
> **产品一句话**：每一轮主聊天结束时，把这一轮已经落在 DSH 会话里的内容写成本机目录树里的 Markdown；聊天本身仍以 DSH 会话为准。

确认方式：看完文末「待拍板」。按默认项回复「按方案做」即可开工；要改的项直接指出编号。

---

## 0. 这是什么

| 是 | 边界 |
|----|------|
| 独立插件。一轮结束就把该轮写成磁盘上的目录和 `对话.md` | 不改 WorkBuddy 引擎，不改其它插件源码 |
| 只读 DSH 会话事件，整理成给人打开的 Markdown | 不另造聊天会话，不把归档喂回 Agent 上下文 |
| 目录按「会话 / 轮次 / 内容或文件」 | 目录名用会话 id 和轮次号，标题写在文件正文里 |
| 落在本机 DSH 家目录下的 `transcripts/` | 不写进当前工程，避免进 git、也不和 `MOM/` 资料库混在一起 |
| 写失败只记日志 | 不因为归档失败打断这一轮对话 |

和现有能力的关系：

| 现有能力 | 本插件 |
|----------|--------|
| DSH 会话日志（刷新、重启可恢复的权威） | 只读。归档是副本，删了不影响聊天 |
| `@zhongruan/dsh-mom-docs` 把用户点名的文档写到工程 `MOM/日期/` | 互不调用。那个要模型按参数落一份文档；这个是每轮自动归档 |
| `@zhongruan/dsh-knowledge` 在 `agent/turn-stopping` 做知识回写 | 挂同一个结束时机，不调用知识库，不追加 `user/message` |
| `@zhongruan/dsh-cursor-coding` / `dsh-cursor-chat` 的本机 Job | P0 不复制 Job 里的思考和改盘过程。工具结果里若已有结论，会随 `tool/result` 出现在 `对话.md` |
| `@zhongruan/dsh-llm-meter` | 不挂 `llm/stream`，不改计量公式和 `events.jsonl` |

## 1. 硬约束

| # | 约束 | 做法 |
| --- | --- | --- |
| 1 | 聊天认 DSH | 不写第二套会话文件给宿主恢复。下一轮模型看不见 `transcripts/` |
| 2 | 不动其它插件 | 新目录、工具前缀 `zr_transcript_`、patch id `transcript`。打包只增加本包 |
| 3 | 契约字段权威 | 轮次只认事件里的 `turn`；用户消息只认 `user/message` 且 `source.kind === 'user'`；工具只认 `tool/call` / `tool/result`。禁止用正文匹配「保存」「取消」来决定写不写 |
| 4 | 终态不被归档改写 | 插件不改会话事件，不改 Job 状态，不改知识库 |
| 5 | 失败不伤对话 | `turn-stopping` 里写盘用 try/catch。异常只 `logger.warn`，不向外抛 |
| 6 | 计量口径冻结 | 不读不写 `dsh-llm-meter`，不包 `llm/stream` |
| 7 | 配置不是凭证账本 | 没有 Key、没有 MES。归档根目录走插件 patch 里的路径，默认 `dshHomePath('transcripts')` |
| 8 | 最小写入面 | 只在归档根下创建会话目录、`会话.md`、`NNN/对话.md`、以及确有附件时的 `NNN/文件/`。不改工作区其它文件 |

## 2. 目录树

默认根目录跟随宿主家目录（与用量插件的 `dshHomePath` 同一套）：

- 本机开发 / 浏览器壳：`~/.dsh/transcripts/`
- 桌面工作助手：进程实际使用的 DSH home 下的 `transcripts/`（以该进程的 home 为准，不写死某一台机器的盘符）

一棵树长这样：

```text
transcripts/
  index.md                          ← 所有会话一行一条，方便总览
  <sessionId>/
    会话.md                          ← 标题、会话 id、工作区、最近更新、各轮链接
    001/
      对话.md                        ← 第 1 轮全文
    002/
      对话.md
      文件/                          ← 仅当本轮消息里有可复制的本地附件才创建
        附图.png
```

这样对应「会话 → 对话（一轮）→ 内容或文件」。

目录名不用会话标题、不用用户原话。标题会变，原话里有 `/`、换行和重名。会话 id、轮次号来自宿主，稳定且不会路径穿越。人要看的名字在 `会话.md` 第一行，总览在 `index.md`。

轮次目录用三位十进制，直接采用事件里的 `turn`（`1` → `001`）。不在插件里另编序号。`turn` 不是正整数时，这一轮不写，并打一条 warn。

同一轮再次结束（宿主重跑该轮）时，覆盖该轮的 `对话.md`。P0 不保留上一次重跑的副本。

`会话.md` 在每次成功写入一轮后重写，内容只有封面，例如：

```markdown
# 报表中心考勤页

- 会话 id：`……`
- 工作区：`/path/to/repo`（没有则省略这一行）
- 最近更新：`2026-10-27T11:20:00+08:00`

## 轮次

- [001](001/对话.md)
- [002](002/对话.md)
```

标题取该会话事件里最后一条 `session/title` 的 `data.title`。还没有标题时，第一行写「未命名会话」。

`index.md` 每次成功落盘后，按归档根下已有会话目录重写，不追加。一行一个会话：标题、会话 id、最近一轮、最近更新时间。重写避免两个会话同时追加把文件写坏；P0 会话量按本机个人使用估计，全量重写可接受。

时间一律用 `Asia/Shanghai`，写成 `+08:00`。不用 UTC 日期切目录。

## 3. 一轮 `对话.md` 里有什么

切轮方式和知识库回写相同：在 `snapshotEvents()` 里找到 `type === 'turn/start'` 且 `data.turn` 等于本轮的那条，取到下一条 `turn/start` 之前的事件。只渲染这一段。不根据压缩后的窗口重写更早的轮次目录，避免宿主压上下文时把已经归档的旧轮改掉。

文件骨架：

```markdown
# 第 1 轮

- 会话：报表中心考勤页
- 会话 id：`……`
- 轮次：1
- 写入时间：`2026-10-27T11:20:00+08:00`

## 用户

（本轮 source.kind 为 user 的 user/message，按事件顺序；多条之间空一行）

## 助手 · 第 1 步

（该轮 assistant/message，按 step 从小到大；没有 step 时按事件顺序，标题写「助手」）

## 工具 · zr_cursor_begin

- callId：`……`

### 参数

（tool/call 的参数文本，超过上限则截断并注明已截断）

### 结果

（与该 callId 配对的 tool/result 正文）
```

字段来源只认事件结构：

| 块 | 认什么 |
|----|--------|
| 用户 | `user/message`，且 `data.message.source.kind === 'user'`。插件自己塞进会话的回声（知识库召回等）不收 |
| 助手 | `assistant/message` 且 `data.turn` 等于本轮。一步一条。正文只拼接 `content` 里 `type === 'text'` 的 `text` |
| 工具 | `tool/call` 的 `data.name`、`data.callId`、参数；`tool/result` 用 callId 配对。对不上的结果单独成节「工具结果（未配对）」 |
| 非文本块 | `content` 里不是 `text` 的块不丢弃类型：在对应消息下写一行「非文本：`<type>`」。P0 不把字节写进 `文件/` |

单份 `对话.md` 的 UTF-8 上限 2 MiB。超出时截断末尾并写明「已截断」。截断不是失败，该轮目录仍然保留。

写盘先写 `对话.md.tmp`，再改名为 `对话.md`，避免写到一半被读成终稿。

用户消息和助手正文都为空、且没有工具事件时，不创建该轮目录。

## 4. 什么时候写

挂 `agent/turn-stopping`。知识库已经用这个时机在轮次结束前拿到 `{ agent, turn }`。本插件在回调里：

1. 读取 `agent.session.snapshotEvents()`，切出该 `turn`。
2. 渲染 Markdown。
3. 原子写入 `transcripts/<sessionId>/<turn>/对话.md`，更新 `会话.md` 和 `index.md`。
4. 任何异常吞掉并 warn。

宿主若没有 `agent/turn-stopping`，或 `snapshotEvents` 不是函数：插件照常加载，不写任何文件，启动时 warn 一次。不改去扫界面、不改去猜正文。这是开工第一天要在桌面工作助手上确认的宿主能力；知识库当前类型声明里两者都有，但是否装进你正在用的桌面宿主，以那天的实测为准。

不订阅 `llm/stream`。那条流里是每一步的整段历史和系统提示，不是「这一轮新写出来的内容」，而且用量插件已经挂在上面。

进行中的流式片段不单独落盘。轮次结束时会话里已经是这一步的成稿。

## 5. 这份归档里不会有的

| 内容 | 原因 |
|------|------|
| 写码 Job 里的思考、工具轨迹、完整 diff | 在本机 Job，不在会话日志。P0 只保存已经写回会话的工具结果 |
| 会话标题生成、网页搜索、知识库抽取、自动化直连、引擎审码 / PCB | 不进主会话事件 |
| 模型每一步收到的系统提示和历史回放 | 不是本轮新产生的可见内容 |
| 工具卡进行中的进度 | 宿主没有单独的进度事件 |

P0 的 `文件/` 默认不出现。消息里的图片、粘贴文件要等看到真实事件里的路径或字节字段，再在 P1 复制到 `NNN/文件/`。复制时只接受归档根之外、解析后仍是普通文件的路径，拒绝符号链接，单文件上限 10 MiB。工作区里被写码插件改过的源码不复制进归档，只在工具结果原文里保留它已经写明的路径。

## 6. 插件形态

| 项 | 值 |
|----|-----|
| 目录 | `plugins/dsh-transcript/` |
| 包名 | `@zhongruan/dsh-transcript` |
| 市场文案 | 中文：把每一轮主聊天存成本机 Markdown 目录。英文：Save each completed chat turn as local Markdown |
| 对话工具 | 一个只读工具 `zr_transcript_where`。无参数。返回当前会话的归档目录绝对路径；该会话还没有目录时返回归档根，并说明尚未写入。不负责触发保存 |
| 界面 | P0 无侧栏、无设置页。用户在资源管理器打开 `transcripts/`，或在对话里问「归档在哪」 |
| 配置 | `cordis.patch.yml`：`enabled: true`，`archiveRoot: dshHomePath('transcripts')`。`enabled: false` 时不注册监听、不注册工具 |

工具只报告路径，不根据用户原话决定写文件。保存只发生在轮次结束的监听里。

日志不打印用户正文、工具参数和密钥。warn 里只留会话 id、轮次和错误类别。

## 7. 分期

### P0（确认后做的全部）

- 新插件骨架：`package.json`（`dsh.bundle` + `dshMarket`）、`cordis.patch.yml`、TypeScript 构建。
- `turn-stopping` → 切轮 → `对话.md` + `会话.md` + `index.md`。
- 渲染纯函数，用夹具事件做自测：用户、多步助手、成对工具、未配对结果、空轮不落盘、标题更新、`turn` 非法不落盘、超过 2 MiB 截断、写盘失败不抛出。
- 只读工具 `zr_transcript_where`。
- 市场打包进清单。本机联调后同步到桌面 profile。

### P1（P0 验收后再开）

- 把已有会话文件（家目录 `sessions/` 下的压缩 jsonl）补成同一棵目录树。只补归档里还没有的会话，不覆盖已有轮次文件。
- 非文本附件：在看过真实事件结构之后，把可定位的本地文件复制到 `NNN/文件/`。
- 可选：`对话.md` 里为写码工具结果中的 `job_id` 加一行本机 Job 路径，仍不复制 Job transcript。

### 不做

- 把归档当聊天记忆或检索库。
- 写进工程目录或 `MOM/`。
- 同一轮保留多次重跑的历史版本（除非拍板改第 2 条）。
- 上传到服务器、飞书或知识库。

## 8. 验收

1. 市场或本地 link 安装后，完全退出工作助手再打开。
2. 新开会话，连续两轮普通对话。磁盘出现 `transcripts/<sessionId>/001/对话.md` 和 `002/对话.md`。`会话.md` 标题与侧栏一致；两轮用户原话和助手正文都在，顺序与界面一致。
3. 再发一轮并让它调用一个会回写结果的工具。`003/对话.md` 里有工具名、callId 和结果正文。
4. 拔掉归档目录的写权限或把根目录指到不可写位置，再完成一轮。对话仍正常结束，日志有 warn，会话本身仍在。
5. 完全退出再打开，已有 `001`、`002` 不被改写；新的一轮只新增下一个轮次目录。
6. 打开一个工程做写码。归档出现在 DSH home 的 `transcripts/`，工程仓库里没有新文件。
7. 问「这一轮存在哪」。回答里的路径等于该会话目录，且该路径下能打开 `对话.md`。

宿主缺少 `turn-stopping` 或 `snapshotEvents` 时，第 2 步不会产生目录。此时停止实施里的「自动落盘」，把实测到的宿主接口记回本文，不改用别的方式猜测轮次。

| # | 项 | 默认 |
| --- | --- | --- |
| 1 | 归档位置 | DSH 家目录 `transcripts/`，不进工程 |
