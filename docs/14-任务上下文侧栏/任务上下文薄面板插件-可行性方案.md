# 任务上下文薄面板插件：可行性方案

> **状态**：P0 已实施（`0.1.28`）；来源仅用户上传特征附件；Profile 已清掉会加载旧逻辑的残留 `src/client.js`；未上架  
> **日期**：2026-11-18  
> **本机验收 Profile（硬）**：macOS 上「江西中软工作助手」实际用  
> `$HOME/AppData/Local/ZR_DSH/dsh-home/profiles/desktop`  
> （进程参数可证）。**不要**只同步 `zr-workbuddy-desktop/.../web` 或 `~/.dsh`。  
> 新插件必须写入该 Profile 的 `package.json` → `dependencies` **且** `dsh.profile.bundles`；  
> 仅 rsync 到 `node_modules` 或只写 `cordis.patch.yml` 不够。  
> **UI 形态（产品纠正）**：对标 Qode **对话右侧薄栏**（`sidebar.right.pane.tab`），  
> **禁止**再挂左侧 `sidebar.panellist` / `main` 导航槽。  
> **兼容并存（硬）**：**不改桌面壳**（不改 `desktop/shell` / 安装包 asar）；只增量注册自己的右侧 tab kind；  
> 不轮询强开、不抢终端/知识库 tab；失败只降级本插件，不影响宿主其它右侧能力。  
> **落点**：本仓库独立 DSH Bundle `@zhongruan/dsh-agent-context`（目录 `plugins/dsh-agent-context/`）  
> **交付形态**：公司插件市场安装。开发机可本地 link 联调；发现页以市场上架为准。  
> **产品一句话**：对话右侧挂一块「任务上下文」面板，聚合本会话的环境/改动、提交入口、技能与连接器、产出与来源；不另造写码引擎、不另造记忆库、不做第二套 IDE Diff。

确认方式：看完文末「待拍板」。回复「按方案做」即按默认项开工；要改的项直接指出编号。

对标参考：Qode 右侧栏（环境信息 + 提交、技能与 MCP、产出、来源、记忆）。

## 0. 这是什么

| 是 | 边界 |
|----|------|
| 独立「薄」插件：几乎只有右侧栏 UI + 极薄只读聚合 | 不跑 Cursor、不写沙箱、不自己 `git commit` |
| 挂宿主 `sidebar.right.pane.tab`（对话右侧薄栏，自动打开）；可选对话输入区小按钮再打开 | **禁止**左侧 panellist/main 导航槽；P0 不改产品壳 |
| 数据只读对账已有插件 HTTP / 宿主 API | 不把本插件 Job / json 当聊天会话权威 |
| 提交按钮只触发写码插件已有 Git 交付 HITL | 不绕过确认卡、不自动 push、不跳过审码门禁 |
| 市场包名独立，版本独立升 | 不把侧栏塞进 `dsh-cursor-chat` 胀包 |

### 和现有能力的关系

| 现有能力 | 本插件 |
|----------|--------|
| `@zhongruan/dsh-cursor-chat` Job / 改动卡 / `gitInspect` / `zr_cchat_git_deliver` | **只读**拉本会话 Job 与工作区摘要；提交走其交付流 |
| `@zhongruan/dsh-esc` 场景/技能/连接器 | **只读** `session-state` / catalog，不在侧栏里改启用逻辑（管理仍在 ESC） |
| `@zhongruan/dsh-knowledge` 右侧 tab 挂载 | **抄挂载模式**，不共用知识库内容 |
| `@zhongruan/dsh-transcript` | P0 可选展示「本会话归档目录」链接；不写归档 |
| 宿主附件 / 右侧工作区 `openResource` | 来源区只列本轮附件；点文件走已有打开工作区能力 |
| WorkBuddy / mneme / 资料库 | P0 **不**做「记忆已更新」动态；P1 再议只读投影 |
| `@zhongruan/dsh-llm-meter` | 不碰；不挂 `llm/stream` |

## 1. 硬约束

| # | 约束 | 做法 |
| --- | --- | --- |
| 1 | 聊天认 DSH（见 `架构与选型/DSH会话与记忆分层.md`） | 不写第二套会话树；侧栏状态用 `sessionId` 对账，刷新后重拉 |
| 2 | 契约字段权威 | 改动列表认 Job `synced_files` / `deleted_files` / git status 路径；取消/终态认 Job `status` / `error.code`。禁止用结论正文正则猜「已取消」 |
| 3 | 终态不可污染 | 面板不 `patch` 已 `succeeded`/`failed` Job；提交失败不改写码业务结果 |
| 4 | 不做第二 IDE | 不做 Monaco Diff、不做侧栏对照编辑、不做 Checkpoint 时间旅行（与写码体验方案「明确不做」一致） |
| 5 | Git 交付不另起炉灶 | 禁止面板内直接 `commit`/`push`；必须进入现有确认卡 + 风险门禁 |
| 6 | 配置不是凭证账本 | 无 MES / LLM / Webhook Key；本地只留调度端口。业务连接仍只读 WorkBuddy `config.yaml`（本插件基本无业务连接） |
| 7 | 最小耦合 | 允许写码插件 **少量只读/入口 API**；禁止把 ESC/写码源码搬进本包 |
| 8 | 失败不伤对话 | 对端插件未装、端口不通、git 失败 → 区块降级文案；不打断聊天 |

## 2. 产品形态（对标 Qode）

右侧栏一个 Tab，标题默认「任务上下文」。按当前 **DSH `sessionId`** 刷新。建议分区自上而下：

```text
┌─ 任务上下文 ─────────────────┐
│ 环境信息                      │
│  +12 -3 · 本地 · hebo         │
│  [提交或推送]                 │
│  工作区路径（可截断）          │
├───────────────────────────────┤
│ 改动                          │
│  • path/a.ts   +8 -1          │
│  • path/b.ts   +4 -2          │
│  （点击 → 右侧工作区打开文件） │
├───────────────────────────────┤
│ 技能与连接器                  │
│  专家：… · 技能 2 · 连接器 1  │
├───────────────────────────────┤
│ 产出                          │
│  本轮结论摘要 / PR 链接 / …   │
├───────────────────────────────┤
│ 来源                          │
│  本轮附件 / 附图              │
└───────────────────────────────┘
```

P0 **不**做「记忆已更新」条（见分期）。

行级 `+N -M`：环境区用工作区 `git diff --shortstat`（相对 HEAD 的工作区脏量）；单文件优先用写码过程已有 snippet 统计，没有则该行只显示路径，不强行猜行数。

## 3. 架构

```text
用户聊天（DSH L1）
        │
        ▼
右侧 Tab：dsh-agent-context（client）
        │  sessionId + workspace
        ├──► dsh-cursor-chat HTTP（Job 列表/详情、workspace-summary、git-deliver 入口）
        ├──► dsh-esc HTTP（session-state / catalog 摘要）
        ├──► 宿主 sessions / 附件 API（若可得）
        └──► （可选）本插件极薄 server：仅端口广播 + 健康检查
                     禁止在此 server 内执行 commit/push
```

### 3.1 为什么单独插件而不是塞进写码

- 侧栏还要展示 ESC、附件、归档等，写码插件不是唯一数据源。
- 写码包已很大；UI 聚合独立演进、独立上架/回滚。
- 知识库已证明 `sidebar.right.pane.tab` 可独立挂载。

### 3.2 对写码插件的「伴侣改动」（允许、须最小）

本面板 **P0 需要** `dsh-cursor-chat` 增加或暴露以下只读/入口能力（不改交付语义）：

| API（建议路径） | 作用 |
|----------------|------|
| `GET /api/cursor-chat/workspace-summary?workspace=&session_id=` | 返回：`is_git`、`current_branch`、`remote_url`（脱敏）、`dirty`、`shortstat`（`+n -m`）、`entries` 路径列表（可复用 `gitInspect` + `git diff --shortstat`） |
| `GET /api/cursor-chat/jobs?session_id=`（若已有则复用） | 本会话最近 Job：`status`、`synced_files`、`deleted_files`、结论摘要字段、PR/compare 链接（已有则透传） |
| `POST /api/cursor-chat/git-deliver/begin-ui`（新建） | 由侧栏触发：按当前 workspace + session 创建与工具同源的 pending + 确认卡所需 token；**之后仍走现有 confirm / risk / cancel** |

面板 **禁止**：自己拼 `git commit` 参数；禁止在无 pending 时假装已提交。

若拍板「P0 提交按钮仅在已有 Git 确认卡等待时可用」，可暂缓 `begin-ui`，改为只读 `git-deliver/awaiting`（现有）高亮「去聊天卡确认」。

### 3.3 ESC

只读：`GET /api/session-state`、`GET /api/catalog`（端口发现方式与 ESC 客户端现有一致）。侧栏展示启用摘要；点「管理」可提示去 ESC 左侧面板，P0 不在侧栏改开关。

### 3.4 打开文件

复用写码客户端已验证路径：`sidebarRight.openResource` / `dsh-resource://file/...` 一类能力。面板内实现一份薄封装即可，不复制 Diff 渲染。

逐文件内容 diff：P0 点开工作区看文件；过程中的 `cc-diff` 片段仍留在聊天进度卡。侧栏不做 hunk 浏览器。

## 4. 插件目录与技术选型

```text
plugins/dsh-agent-context/
  package.json          # @zhongruan/dsh-agent-context，dsh.bundle + dshMarket.zh/en
  cordis.patch.yml
  src/
    index.ts            # 注册入口
    client.ts / client.js
    docked-panel.ts     # 参考 dsh-knowledge docked-panel-compat
    panel-ui.ts         # 分区渲染
    peers.ts            # 发现 cursor-chat / esc 端口
    types.ts
  test/                 # 纯函数：shortstat 解析、空态、对端缺失降级
  README.md
```

- 语言：与仓库其它插件一致（TypeScript 构建；客户端可 TS 编译或薄 JS）。
- 工具前缀（若需要）：`zr_acontext_`；P0 **可以没有对话工具**，仅 UI。
- 无业务 Key；`config.json` 最多留 UI 开关（如默认是否自动打开 Tab），非正式凭证源。

## 5. 空态与降级

| 情况 | 展示 |
|------|------|
| 未装 / 未启动写码插件 | 环境与改动区：「写码插件未就绪」；提交按钮禁用 |
| 非 git 工作区 | 分支显示「非 Git 仓库」；提交禁用；改动仍可显示 Job `synced_files` |
| 无脏文件且无本会话 Job 改动 | 改动区：「暂无改动」 |
| 未装 ESC | 技能区折叠或「专家技能插件未安装」 |
| 无附件 | 来源区隐藏或「无」 |
| 提交进行中 | 按钮禁用；文案跟 Job/pending 状态，不扫正文 |

## 6. 分期

### P0（确认后实施范围）

1. 新插件骨架 + 右侧 Tab「任务上下文」。
2. 环境信息：分支、本地、shortstat、工作区。
3. 改动列表：本会话最近相关 Job 文件 ∪ git dirty 路径；点击打开工作区。
4. 提交或推送：默认走「伴侣 API `begin-ui` → 聊天确认卡」（待拍板可改为仅 awaiting）。
5. 技能与连接器：ESC 只读摘要。
6. 产出：最近成功/进行中 Job 的结论短摘要、已同步文件数、若有 compare/PR URL 则展示链接。
7. 来源：能拿到的本轮宿主附件列表；拿不到则 P0 隐藏整区。
8. 自测：shortstat 解析、对端缺失降级、session 切换清空串台。
9. **不上架**，除非你明确发令；默认只改仓库。

### P1

- 产出聚合：transcript 路径、`dsh-dev-pipeline` 制品链接、审码报告路径。
- 来源：知识库挂载 / `@` 引用（若宿主可枚举）。
- 写码进度卡与侧栏改动列表的轻度联动（打开侧栏、高亮当前文件）。
- 可选：设置项「写码开始时自动打开任务上下文」。

### P2 / 需另行拍板

- 「记忆已更新」只读条（须宿主或 mneme 事件可订阅；禁止自建 memory.db）。
- 完整 Diff 浏览器 / 第二 IDE（当前文档冻结为不做）。

### 明确不做（本方案周期内）

- 在面板内直接 commit/push/改 remote。
- 把侧栏状态写进 DSH 会话当第二记忆。
- 改 `dsh-llm-meter` 口径或用量页。
- 未口令自动 pack+upload / 覆盖本机 Profile。
- 为验收启动源码桌面。

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| 与知识库抢右侧 Tab | 独立 `kind`/`id`；用户可切换 Tab；不强制关闭知识库 |
| 端口发现脆弱 | 与现网写码/ESC 同一约定（如 localStorage 端口键）；失败降级 |
| `begin-ui` 绕过 HITL | 实现时强制复用 pending + 现有 confirm；自测断言无直接 commit |
| session 串台 | 所有请求带 `session_id`；Tab body 绑当前 session；不可见 Tab 不轮询（同 knowledge） |
| 行数统计不准 | shortstat 只表示工作区相对 HEAD；与「本轮 Job 已同步」可能不一致——UI 文案写清「工作区未提交改动」 |

## 8. 验收（P0）

1. 安装/link 本插件 + 已有写码插件，完全退出安装版客户端再开。
2. 打开某 git 工程会话：右侧可开「任务上下文」，见分支与 shortstat。
3. 完成一轮写码同步后：改动区出现文件；点击能在右侧工作区打开。
4. 点「提交或推送」：聊天出现与现网一致的 Git 确认卡；未确认前无新 commit。
5. 确认并走完交付（或取消）：面板状态刷新；取消后工作区改动仍在。
6. 卸载或停掉 ESC：技能区降级，其它区仍可用。
7. 切换会话：面板数据不串到上一会话。
