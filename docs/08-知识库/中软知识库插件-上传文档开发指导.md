# 中软知识库插件：上传文档开发指导

> **给谁**：独立 DSH 插件仓（建议包名 `@zhongruan/dsh-knowledge`），**不是** DSH-ZR-WorkBuddy 本仓。  
> **目标**：在已验证可用的 `@lemoncat7/dsh-knowledge@2.9.6` 上增加「导入文件 → 可检索知识文档」，整包替换上游，用户不必自己装市场插件。  
> **WorkBuddy 侧后续**：预装从 lemoncat7 改钉中软包（只改接线脚本，不把插件源码倒进 WorkBuddy）。

本文按 **2.9.6** 已装包核对。上游仓库：https://github.com/lemoncat7/dsh-knowledge（MIT）。

---

## 0. 先读懂：不是「对接」两个插件

DSH 聊天壳只认 **profile 里装了哪个 npm 包**、`cordis.patch.yml` 里 **`id: knowledge` 指向谁**。

| 错误理解 | 正确做法 |
|---|---|
| `@zhongruan/dsh-knowledge` 运行时去调 lemoncat7 | **不要**。两个包不要同时装 |
| 上传走中软、检索走 lemoncat7 | **不要**。会抢侧栏、抢 `id: knowledge` |
| fork 源码、改名发布、WorkBuddy 改预装钉你们的包 | **要这样** |

关系图：

```text
用户装 WorkBuddy
    → profile 只装 @zhongruan/dsh-knowledge（替代 lemoncat7）
    → Cordis 仍是 id: knowledge
    → 本机仍是 ~/.dsh/.../knowledge/knowledge.sqlite
    → 侧栏「知识库」+ 项目/会话挂载 + 召回
    → 新增：导入文件 → POST entries（和「新建文档保存」同一条路）
```

## 1. 开仓与改名（第一天）

### 1.1 拿到源码

任选：

```bash
# 推荐：从 npm 打包对照 2.9.6
npm pack @lemoncat7/dsh-knowledge@2.9.6
# 解压后作为起点，或 git clone 上游后 checkout 对应 tag/commit
```

本机已装位置（只读对照，**不要在这里改长期交付**）：

- `~/.dsh/profiles/web/node_modules/@lemoncat7/dsh-knowledge/`

### 1.2 必须改的标识

| 文件 | 改什么 |
|---|---|
| `package.json` `name` | `@zhongruan/dsh-knowledge` |
| `version` | 从 `2.9.6` 起自己的版本，例如 `1.0.0` |
| `cordis.patch.yml` 里 `name:` | 必须等于 **npm 包名** `@zhongruan/dsh-knowledge` |
| `cordis.patch.yml` 里 `id:` | **保持 `knowledge`**（与 WorkBuddy 预装的 `- id: knowledge` 对齐） |
| `repository` / README | 改成中软仓，注明 fork 自 lemoncat7、MIT |

`dsh.client.inject`、`dsh.bundle.patch` 结构不要拆掉，否则侧栏进不来。

### 1.3 Cordis 默认配置（务必完整）

上游包自带：

```yaml
- insert:
    - id: knowledge
      name: '@zhongruan/dsh-knowledge'   # 只改 name
      config:
        backend: local
        databasePath: !!js dshHomePath('knowledge/knowledge.sqlite')
        connectionPath: !!js dshHomePath('knowledge/connection.json')
        exposeApi: false
        exposeWeb: true
        extractionEnabled: true
```

WorkBuddy 当前宿主是 **`dsh` 0.1.1-rc.2**。回写会调 `session.snapshotEvents()`，该版本没有此方法，回答底部会报「未能可靠入队」。

**建议中软包默认：**

```yaml
        extractionEnabled: false
```

用户 patch 若覆盖 `- id: knowledge` 整块，**必须自带 `databasePath` + `connectionPath`**，否则宿主启动即崩：`local knowledge backend requires databasePath`（WorkBuddy 踩过）。

### 1.4 数据兼容

继续用同一 `databasePath`，则用户已有知识库、挂载、文档 **还能用**。  
不要改 SQLite schema 除非你们做迁移。

## 2. 两条「文档」不要搞混

插件里有两套存储，**检索问答只吃知识文档**：

| | 知识文档（要导入到这里） | 笔记（已有上传，但不能当 RAG） |
|---|---|---|
| 界面 | 「03 知识文档」「06 知识库与挂载」里的库/文档树 | 「笔记文档」工作区 |
| 创建 API | `POST …/entries` body `{ draft }` | `POST …/notes/documents` 或 `POST …/notes/files` |
| 进 FTS / 挂载召回 | **是** | **否**（笔记不进自动召回） |

P0 **禁止**把用户选的 PDF 只丢进笔记区交差。必须变成 **knowledge entry**。

管理台同源 API 前缀（浏览器走这个，不要求开放远程 API）：

- `LOCAL_MANAGEMENT_API_PREFIX = '/knowledge-local/v1'`
- 见 `lib/api.js` 的 `registerKnowledgeApi`

创建知识文档（与「新建文档 → 创建文档」相同）：

```http
POST /knowledge-local/v1/entries
Content-Type: application/json

{
  "draft": {
    "knowledgeBaseId": "<当前库 id>",
    "title": "文件名去掉扩展名，1～200 字",
    "body": "纯文本/Markdown，1～50000 字",
    "type": "fact",
    "tags": [],
    "scope": { "kind": "global" },
    "confidence": 0.8
  }
}
```

实现落点：

- 路由：`lib/api.js` → `POST` + `segments[0] === 'entries'` → `provider.create(parseDraft(body.draft))`
- 入库：`lib/local-provider.js` → `insertEntry` → `upsertFts`
- 前端现有保存：`web/app.js` → `saveDocumentEditor` → `api('entries', { method: 'POST', body: { draft } })`

`type` 只能是：`preference` | `fact` | `decision` | `procedure` | `lesson`。导入默认用 **`fact`**。

## 3. 硬限制（导入前必须处理）

| 限制 | 值 | 含义 |
|---|---|---|
| JSON 请求体 | `MAX_BODY_BYTES = 1_048_576`（1 MiB） | `POST entries` 走 JSON；大文件不能整包塞进 draft |
| 正文 `body` | **1～50000 字符**（`normalizeDraft`） | 超长文件必须 **切成多篇** 或提高上限并评估 FTS |
| 标题 `title` | **1～200 字符** | 用文件名，过长截断 |
| 知识库 | 必须是 **status=active** 的库 | 没有当前库则先提示「请先选/建知识库」 |

P0 建议：

- `.md` / `.txt` 按 UTF-8 读文本。  
- `body.length > 50000`：按标题/空行切成多条 `entries`，标题用 `原名 (2)`、`原名 (3)`。  
- 单文件解码后超过例如 2MB 文本：直接失败并提示，不要撑爆页面。

## 4. P0 功能规格

### 4.1 用户路径

1. 侧栏打开「知识库」。  
2. 进入 **知识文档** 或 **知识库与挂载**（已选中某个库）。  
3. 在「+ 新建文档」旁增加 **「导入文件」**。  
4. 系统文件选择器，**可多选**。  
5. P0 扩展名：`.md` `.txt`（大小写不敏感）。其它扩展名跳过并汇总失败原因。  
6. 导入成功后刷新文档树，可点开正文；到已挂载该库的会话里提问应能命中。

### 4.2 UI 落点（对照 2.9.6）

文件：`web/app.js`

已有按钮文案「新建文档」，例如：

- 库详情：`actionButton('+ 新建文档', () => { void startBlankDocument(...) })`（约 1410 行）  
- 文档树：`startBlankDocument`（约 1713、1736、1759 行）

在这些位置 **并列** 加「导入文件」，不要塞进笔记工作区的 `importDroppedNotes`（那是笔记拖放）。

建议：

- hidden `<input type="file" multiple accept=".md,.txt,text/plain,text/markdown">`  
- 点击「导入文件」触发 `input.click()`  
- `change` 后对每个 `File`：`file.text()` → 调新建的 `importKnowledgeFiles(workspace, baseId, files)`  
- 导入中 Toast：「正在导入 n/m」；结束：「成功 x，失败 y」

可选：知识文档树区域 `drop` 文件（`DataTransfer.files`），同样走 `importKnowledgeFiles`，不要和笔记 drop 混用。

### 4.3 前端 API 调用

管理台已有 `api(path, options)`（`web/api-client.js`）。导入循环：

```js
await api('entries', {
  method: 'POST',
  body: {
    draft: {
      knowledgeBaseId: baseId,
      title,
      body,
      type: 'fact',
      tags: ['imported'],
      scope: { kind: 'global' },
      confidence: 0.8,
    },
  },
})
```

成功后 `await reloadDocumentWorkspace(workspace)`（已有函数）。

同名策略 P0：**允许重复标题**（上游同名不挡创建）。若要「覆盖」，先 `GET documents` / document-index 按标题找再 `PUT entries/:id`，P0 可不做。

### 4.4 后端要不要新接口

P0 **可以不新增路由**：浏览器读文本后 `POST entries` 即可。

若要支持较大文件或 PDF 二进制，再加例如：

```http
POST /knowledge-local/v1/knowledge-bases/:id/import
Content-Type: application/octet-stream
X-Filename: quote.md
```

在 `lib/api.js` 用 `readBinary`（笔记文件上限 64MiB 可参考），解析成文本后再 `provider.create(...)`。  
**不要**复用 `POST /notes/files`。

## 6. 构建、测试、发布

上游脚本（保持能跑）：

```bash
npm install
npm test          # 先保证 fork 后未改坏
npm run build     # web/app.js check + tsc + build-client
npm pack --dry-run
```

**必须加的测试（插件仓）：**

1. `provider.create` / `insertEntry`：给定 title+body，FTS 能搜到关键字。  
2. 超长 body（>50000）被拒绝或被切成多篇（按你们实现二选一写断言）。  
3. 若新 import 路由：md 文件 → 201 + 列表可见。

**手工验收（装进 `dsh` profile）：**

```bash
# 先卸 lemoncat7，避免双开
dsh plugin --profile web add @zhongruan/dsh-knowledge@<version>
# 重启 dsh web
```

1. 打开侧栏知识库，页面不是 `Failed to load plugins`。  
2. `package.json` 的 `dsh.client` 必须能解析到 `client.js`（市场装失败常见原因：bundles 有名、node_modules 无包）。  
3. 选一库 → 导入一篇含独特词「WorkBuddyImportXYZ」的 md → 文档树出现。  
4. 「项目与会话挂载」挂上该库（召回开）→ 新会话问该词 → 答得上。  
5. 回答底部不应再因 `snapshotEvents` 刷红（`extractionEnabled: false`）。

WorkBuddy 当前预装会写 `extractionEnabled: false` 且要求 `databasePath`；你们的 bundle 默认也应自洽。

## 8. 明确禁止

1. 两个知识库插件长期并存（lemoncat7 + 中软，或再加 `dsh-knowledge-base`）。  
2. 只把文件传到 **笔记** 区。  
3. 改 DSH 内核 / 把业务焊进 `mes-bridge`。  
4. 在 WorkBuddy 的 `features/` 里 `import` 本插件。  
5. 为上传再自研一套向量库（召回继续用上游 FTS）。  
6. 用户 patch 只写 `extractionEnabled` 而丢掉 `databasePath`。
