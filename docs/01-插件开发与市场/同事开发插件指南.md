# 同事开发插件指南（照做即可）

> **给谁看**：拿到本仓库、要做公司 DSH 插件并上架「插件市场」的同事。  
> **一句话**：在 `plugins/` 里按模板写 Bundle → 本机联调 → `pack` → `upload` → 用户在市场点安装。  
> **模板位置**：仓库根目录 [`templates/dsh-plugin-starter/`](../../templates/dsh-plugin-starter/)  
> **更新**：2026-09-29（目录已迁到 `plugins/`）

---

## 0. 先建立正确预期

| 你要做的 | 说明 |
|---|---|
| 写的是什么 | **DSH Bundle 插件**（聊天壳「设置 → 插件市场」里装） |
| 不是什么 | 不是 WorkBuddy 引擎里的「功能插件 / features」；不要塞进 `mes-bridge` |
| 用户怎么用 | 市场点「安装」或「更新」，**不用**每次重装桌面软件 |
| 本地 `dsh plugin add ./` | 只适合你自己联调；**同事发现页看不到**，正式交付必须 `pack` + `upload` |
| 凭证往哪填 | MES / LLM / 企微 / 飞书等只读 WorkBuddy **系统配置**；插件里不要再做第二套填写页 |

```text
开发机写代码
    → pack 生成公司目录 + 私有 npm
    → upload 推到 175.178.238.31
    → 用户浏览器/桌面打开宿主 → 设置 → 插件市场 → 安装/更新
```

## 2. 命名规矩（必须遵守）

| 项 | 规则 | 例子 |
|---|---|---|
| 源码目录 | 只允许 `plugins/dsh-<短名>/` | `plugins/dsh-hello/` |
| npm 包名 | `@zhongruan/dsh-<短名>` | `@zhongruan/dsh-hello` |
| 市场文案 | `package.json` 里 `dshMarket.zh` / `dshMarket.en` | 发现页显示的中英文简介 |
| Bundle 声明 | 必须有 `dsh.bundle.patch` | 否则 `pack.sh` 扫不到 |
| 工具名 | 建议带前缀，全公司勿撞名 | `zr_hello_greet` |
| patch `id` | 组合树唯一 | `hello`（别和别人重复） |

短名用小写字母、数字、连字符；**不要**用中文、空格、路径斜杠。

## 3. 从模板开一个新插件（推荐路径）

下面用「问候示例」演示。你把 `hello` 换成自己的短名即可。

### 3.1 复制模板

在**仓库根目录**执行：

```bash
cd /path/to/pythonProject_dsh_plugin

# 复制模板 → 正式插件目录（名字必须 dsh- 开头）
cp -R templates/dsh-plugin-starter plugins/dsh-hello

cd plugins/dsh-hello
```

### 3.2 改包身份（四处对齐）

打开并修改：

**① `package.json`**

- `"name"` → `@zhongruan/dsh-hello`（或你的短名）
- `"version"` → 首次 `0.1.0`；以后每次上架前**必须升高**
- `"description"` → 一句话说明
- `"dshMarket.zh"` / `"dshMarket.en"` → **发现页文案**（用户最先看到的是这个）

**② `cordis.patch.yml`**

- `id` → 例如 `hello`
- `name` → **必须与** `package.json` 的 `name` **完全一致**（含 `@zhongruan/`）

**③ `src/index.ts`**

- `export const name` → 内部短名（可与目录短名一致）
- 工具 `name` / `description` / 业务逻辑按需求改

**④ 确认结构**

```text
plugins/dsh-hello/
├── package.json
├── cordis.patch.yml
├── tsconfig.json
├── .gitignore
├── src/
│   └── index.ts
└── lib/                 ← pnpm build 后生成，勿手改
```

### 3.3 安装依赖并编译

```bash
cd plugins/dsh-hello
pnpm install
pnpm build
# 应出现 lib/index.js
```

编译不过：**先修 TypeScript，不要 pack。**

## 4. 模板里代码在干什么（读懂再改）

模板 [`templates/dsh-plugin-starter/src/index.ts`](../../templates/dsh-plugin-starter/src/index.ts) 注册了一个对话工具 `zr_hello_greet`：

| 概念 | 白话 |
|---|---|
| `export const name` | 插件在 Cordis 里的名字 |
| `inject = ['tools']` | 我要用「工具注册」能力 |
| `apply(ctx)` | 插件装上时执行：在这里 `ctx.tools.register(...)` |
| `defineTool` | 告诉模型：工具叫什么、参数是什么、怎么执行、结果怎么展示 |
| `description` | 写清楚**何时该调、何时别调**；模型主要靠这个判断 |

扩一个工具时：在 `apply` 里再 `register` 一个 `defineTool` 即可。  
需要侧栏 UI、HTTP 服务时，可对照现有插件（如 `plugins/dsh-esc`、`plugins/dsh-automations`），本文以「工具型」为主。

### 4.1 业务凭证怎么读（重要）

若工具要连 MES / 调模型 / 发企微：

- ✅ 读 WorkBuddy 引擎 `config.yaml`（界面：**系统配置**）
- ❌ 不要在插件面板再要用户填 Key、Webhook、MES Base URL
- 未配置时提示用户去 **系统配置** 对应页，不要指去「插件推送配置」

可参考：`plugins/dsh-automations/src/workbuddy_config.ts`。

## 5. 本机联调（不上架也能验）

联调只影响**你自己的** DSH Profile，不会进公司发现列表。

### 5.1 启动宿主

常用两种：

- **WorkBuddy 开发聊天壳**：本机 `http://127.0.0.1:3081`（由 WorkBuddy 的 `scripts/host.sh up` 拉起）
- 或你司约定的浏览器宿主地址

确认「设置」里能打开 **插件市场**。

### 5.2 本地安装你的插件

在**仓库根**执行（路径要对，不要多套一层目录）：

```bash
cd /path/to/pythonProject_dsh_plugin

# 正确：指向 plugins 下的目录
dsh plugin --profile web add ./plugins/dsh-hello

# 错误示例（不要这样）：
# cd plugins/dsh-hello && dsh plugin add ./dsh-hello   ← 路径不存在
```

装完后：**完全退出并重启**宿主（或重启 WorkBuddy），再开新对话。

### 5.3 对话验收

新开会话，例如说：

> 请调用问候工具，称呼用「张三」

期望：模型调用 `zr_hello_greet`，回复里出现模板那句问候。

### 5.4 改代码后如何刷新

```bash
cd plugins/dsh-hello
pnpm build
# 再执行一次本地 add（或卸了重装），然后重启宿主
dsh plugin --profile web add ./plugins/dsh-hello
```

## 6. 正式上架：打包 → 上传 → 核对

这是**交付闭环**。少一步，发现页就没有你的插件。

### 6.1 上架前自检

- [ ] 目录在 `plugins/dsh-<短名>/`
- [ ] `package.json` 有 `dsh.bundle` 与 `dshMarket.zh` / `en`
- [ ] `version` 已升高（相对线上；首次可为 `0.1.0`）
- [ ] `pnpm build` 通过
- [ ] 本机联调工具能被调用
- [ ] 没有把密钥写进仓库

### 6.2 打包（仓库根执行）

```bash
cd /path/to/pythonProject_dsh_plugin

# 只打你的包（推荐）；脚本仍会把已有其它插件写进目录，避免冲掉线上包
./scripts/internal-market/pack.sh dsh-hello
```

成功时你会看到类似：

```text
==> 构建 dsh-hello
==> 制品已就绪: .../company-registry/artifacts/zhongruan-dsh-hello-0.1.0.tgz
已生成 plugins.json，共 N 个插件
```

`pack.sh` 会顺带跑 `generate-registry.sh`，生成：

- `company-registry/plugins.json`（市场目录）
- `company-registry/npm/@zhongruan/...`（含 `latest`，给「更新」按钮用）
- `company-registry/artifacts/*.tgz`

### 6.3 上传到公司服务器

```bash
./scripts/internal-market/upload.sh
```

脚本会：

1. 对比本地与线上目录，**防止误删别人已上架的插件**
2. `scp` / `rsync` 推到 `175.178.238.31` 的 `/www/wwwroot/dsh-plugins/`
3. 逐个核对每个包的 `…/npm/@zhongruan/<包>/latest` 是否等于目录里的版本

全部 `OK …@latest → x.y.z` 才算上传成功。

**不要**默认加 `FORCE=1`。只有产品明确要**下架**某个插件时才用：

```bash
FORCE=1 ./scripts/internal-market/upload.sh
```

### 6.4 线上核对（你自己 curl）

```bash
# 目录里有没有你的包
curl -sS http://175.178.238.31/dsh-plugins/plugins.json | python3 -m json.tool | less

# 更新检测依赖的 latest
curl -sS "http://175.178.238.31/dsh-plugins/npm/@zhongruan%2fdsh-hello/latest"

# 制品能否下
curl -sS -o /dev/null -w "%{http_code}\n" \
  "http://175.178.238.31/dsh-plugins/npm/@zhongruan/dsh-hello/-/dsh-hello-0.1.0.tgz"
# 期望 200
```

### 6.5 在插件市场验收（用户视角）

1. 打开宿主（浏览器或桌面）→ **设置 → 插件市场 → 发现**
2. 搜你的中文文案或包名短名
3. 点 **安装**，装完重启宿主（若界面要求）
4. 新对话验证工具

发新版后：发现页版本升高 → 已装用户点 **更新**（依赖私服 `/latest`，你们 `generate-registry` 已自动落盘）。

## 7. 日常发新版（最短路径）

```bash
# 1) 改代码
cd plugins/dsh-hello
# 编辑 src/…

# 2) 升版本（必做）
# 改 package.json 的 "version"：0.1.0 → 0.1.1

# 3) 编译
pnpm build

# 4) 打包 + 上传（仓库根）
cd ../..
./scripts/internal-market/pack.sh dsh-hello
./scripts/internal-market/upload.sh

# 5) 市场点「更新」或卸了重装
```

开发机想立刻覆盖本机旧缓存（非终端用户路径）：

```bash
./scripts/internal-market/install-latest.sh dsh-hello
```

终端用户正常只走市场「更新」。

```json
{
  "name": "@zhongruan/dsh-hello",
  "version": "0.1.0",
  "dshMarket": {
    "zh": "发现页中文简介",
```


## 9. 常见问题（先看这里）

| 现象 | 常见原因 | 怎么办 |
|---|---|---|
| `pack.sh` 找不到插件 | 不在 `plugins/`，或没有 `dsh.bundle` | 目录改成 `plugins/dsh-xxx`，补 `dsh.bundle` |
| 市场「发现」没有 | 只本地 `add` 没 `upload` | 走 pack + upload，再刷发现页 |
| 有条目但装不上 | npm / tgz 404 或版本不一致 | curl `latest` 与 tgz；重新 pack+upload |
| 装了但对话不调工具 | 没重启宿主；description 写糊；工具名冲突 | 重启；改清晰 description；查是否重复注册 |
| 点不了「更新」 | 线上缺 `/latest` 文件 | 用当前 `generate-registry`（会写 latest）再 upload |
| upload 报「本地缺少线上插件」 | 你本地目录比线上少包 | 先在本机 pack 齐；**不要**随便 `FORCE=1` |
| 同事装到旧版 | version 没升；或宿主缓存 | 升 version 再 upload；对方点更新或卸重装 |
| 相对路径 add 失败 | `cd` 进插件后再 `add ./dsh-xxx` | 在仓库根：`add ./plugins/dsh-xxx` |
