# 对标企业级 AI-Coding · 差距与排期

> **日期**：2026-11-15（2026-11-16 修订：可写范围已验；Git 出口口径见专项方案）  
> **现行交付**：`@zhongruan/dsh-cursor-chat`（手册口径约 **0.3.70**）  
> **对标标尺**：企业级 AI-Coding 平台（组织治理 + 研发流水线 + 合规审计 + 规模运营），**不是**「再逼近 Cursor IDE 一截」。  
> **产品边界**：接 Cursor 写码，挂在 DSH 聊天壳；**不做第二 IDE**（无 Monaco Diff / `@` 引用 / 完整终端面板）。  
> **用途**：产品与排期对照；不替代主流程冻结口径。

---

## 0. 一句话结论

| 对标对象 | 结论 |
| --- | --- |
| Cursor 个人 Agent | **已可用**：写码手同源；过程观感约七成；故意多出门禁（澄清 / HITL） |
| 企业 AI-Coding 平台 | **单机交付可信度靠前**；缺 **组织策略、Git/PR/CI、合规审计、规范/知识强制注入、规模运营** |

差距主要不在「会不会改代码」，而在 **可控、可审、可进流水线、可规模化**。

## 1. 已接近企业级的能力（现状）

依据现行手册与实现，下列能力已可作为对外「企业向」卖点（相对个人 IDE Agent）：

| 维度 | 现状 |
| --- | --- |
| 人机门禁 | 澄清 → HITL 确认 → 才写盘（确认前不改真工程） |
| 落盘可控 | 沙箱改盘 → **项目画像自动可写范围**（`auto` / `open`）→ 敏感硬拒 + `auto` 软放行 → 默认同步；显式 `writeScope` 为 `config` 硬闸；亦可 `pending_review` → apply |
| 交付可信 | 交付审计 + 可修项自动续修（`api_mount` / `param_contract` / `schema_drift` / 菜单等）；落盘硬闸挡假绿；敏感仅沙箱时结论标明「安全拦截」 |
| 工程适配 | `projectLayout` 唯一布局入口；嵌套前后端 / 灵活目录，禁止写死顶层路径误杀；**可写范围已跟画像联动（2026-11-16 本机验过）** |
| 开发闭环 | 写码走沙箱；重启 / 测 / 日志 / 装依赖 / 排障走真实工程终端 |
| 多轮续改 | `zr_cchat_continue`，同会话优先 `Agent.resume`；可贴图 |
| 安全底线 | HITL nonce；路径拒绝 `..` / 盘符 / `~`；正式模式禁静默 Mock；取消 / 终态只认权威字段 |

相对个人 Cursor：**门禁与交付验真更强**；相对完整企业平台：仍缺组织面与流水线面。

## 2. 差距总表（按优先级）

### P0 · 组织级治理（当前≈本机个人工具）

| 缺口 | 现状 | 企业级期望 |
| --- | --- | --- |
| 密钥与策略中心化 | Key / 端口在 `~/.zhongruan/cursor-chat/config.json`；**可写范围默认按项目画像自动**（显式 `writeScope` 仍为硬闸）。组织下发**后置** | 企业统一发放、轮换、吊销；组织级 allow/deny（路径、命令、外网）盖在自动范围之上 |
| 身份与权限 | 本机用户即全权 | SSO / 账号角色：谁可开写、谁可扩 scope、谁可跳过审；CODEOWNERS / 目录责任人联动 |
| 合规审计账本 | 本机 Job 账本（`jobs/`） | 可导出「谁、何时、哪仓、审过没、同步没」；留存与检索策略 |

企业买的是 **可控**，不只是 **能改**。

### P1 · 研发流水线（Git / PR / CI）

| 缺口 | 现状 | 企业级期望 |
| --- | --- | --- |
| 分支 / 提交 / PR | **默认同步工作区**；用户明确「提交/开 PR」走 `zr_cchat_git_deliver`（确认卡默认展示当前仓库地址与分支 → 人审 → commit/push/PR） | 需要时可审：分支 → 人审确认 → commit → PR；**不**强制每轮 PR |
| CI 硬闸 | 聊天可「跑一下测」；交付审计偏业务假绿 | lint / typecheck / test / 约定 CI 红绿作为交付条件 |
| 回滚 | 沙箱可留；产品化回滚弱 | Job 级 checkpoint / 一键还原 / 按同步批次回退 |
| 文件级审改默认 | 能力有（`pending_review`），产品默认偏自动同步 | 企业常默认「证清单再落盘」；超时策略可配置 |

### P2 · 上下文与规范资产

| 缺口 | 现状 | 企业级期望 |
| --- | --- | --- |
| 项目 Rules / 编码规范 | 未产品化为强制注入 | 对标 Cursor Rules / 企业自定义指令；按仓 / 目录强制带入 |
| 知识库联写码 | 知识库独立插件；边界清晰、未打通一条产品路径 | 写码轮次自动检索领域文档 / 接口约定 |
| 多仓协同 | 以当前工作区为准 | 多仓 / monorepo / 依赖仓改动编排 |
| 规格工件 | 对话驱动 + 澄清题 | 可归档的方案 / 影响面报告 → 再确认开写 |

### P3 · 质量门禁加厚

现有审计对 **FastAPI + 前端业务假绿** 有差异化优势。企业通用层还缺：

- 按技术栈画像开关的 **typecheck / lint / test 硬门**
- E2E / 浏览器验（贴图已有，系统验弱）
- 密钥扫描、依赖漏洞、许可证策略进交付

### P4 · 规模化运营

| 缺口 | 说明 |
| --- | --- |
| 配额打通 | Cursor 写码消耗与 `dsh-key-quota`（用量统计 / 限额）是否产品化联动，需说清 |
| 可观测 | 团队成功率、审计失败率、续修轮次、取消率看板 |
| 并发与隔离 | Job 公平排队；共享开发机多用户数据面隔离 |
| 私有化策略 | 断网 / 模型白名单 / 供应商策略（当前绑 Cursor Local SDK） |

| 项 | 口径 |
| --- | --- |
| IDE Diff / `@文件` / 完整终端 UI | DSH 壳边界；**不做第二 IDE** |

## 4. 建议排期（可裁剪）

> 默认只改仓库文档与产品方案；实现须另开任务。未获「上架」口令不得 pack+upload。

### 已落地（本机）

- **项目画像自动可写范围**（`auto` / `open` / 显式 `config` 硬闸；敏感拦截与结论提示）— 2026-11-16 本机验收通过

### 第一优先（最有「企业级」观感）

1. **Git 交付出口**（✅ v1 已实现）：平时仍只同步工作区；用户明确「提交代码 / 开 PR」→ `zr_cchat_git_deliver` → 确认卡（默认当前仓库/分支）人审 → commit → push → 尝试开 PR。详见 [写码插件-Git交付出口方案.md](./写码插件-Git交付出口方案.md)  
2. **CI / 约定测试硬闸**（← **当前下一刀**）：画像识别到的测试命令进交付审计；失败可续修或挡「已完成」  
3. **合规导出**：按账号 / 时间 / 工程导出 Job 与同步文件清单

### 第二优先

4. 默认 `pending_review` 策略可按组织开关（效率仓 vs 受控仓）  
5. Job 级回滚（同步前快照 / 同步清单反向）  
6. 项目 Rules 强制注入 + 与 `dsh-knowledge` 的「写码时检索」产品路径  
7. Cursor 消耗进 `dsh-key-quota` 展示与限额（认用量统计权威插件，不改 `dsh-llm-meter` 冻结口径）

### 可后置 / 观察

8. **组织写权限策略**（组织 allow/deny 盖在本机 `auto`/`open` 之上）— **2026-11-16 产品决定后置**（人数少、本机自动范围已够用）  
9. 多仓编排、E2E 浏览器验、共享机多用户隔离、断网私有化  
10. 跑中 steer（依赖 SDK 能力核实后再做）

### 明确不排

- 再造 Diff 面板、侧栏文件树、Checkpoint 时间旅行式 IDE 体验  
- 为工具行「更像 Cursor」做无效字段映射

## 6. 对外说法建议

- ✅「在 DSH 里确认后，由 Cursor 在本机工程改码；改完会验真，假绿会挡或自动续修。」  
- ✅「平时同步到工作区；你说提交/开 PR 时再走分支和评审，不是每次都强制 PR。」  
- ✅「单机交付闭环已偏企业向（门禁 + 沙箱范围 + 审计）；组织策略后置；Git/PR 按需出口与 CI 仍是下一阶段。」  
- ❌「已经是完整企业级 AI-Coding 平台。」  
- ❌「再把进度卡做成和 Cursor IDE 一样就算企业级。」  
- ❌「每次 AI 改完都必须开 PR。」
