# 写码插件输出 VS Cursor 原生输出 · 对比报告

> **日期**：2026-09-13  
> **对照对象**  
> - **插件**：`@zhongruan/dsh-cursor-coding`（联调口径约 **0.6.40～0.6.41**；主流程已冻结）  
> - **原生**：Cursor IDE 内 Agent / Composer 对话面板（同模型族 Local Agent 能力）  
> **证据来源**：同业务样例（报表中心 / 员工工时等）真人联调进度卡与正文结论；Job 账本 `tool_event` / `transcript` 抽样（如 `ccj-20260913-094244-db8d`）；SDK 类型与流事件对照。  
> **产品口径**：接 Cursor 写码，不是再造 IDE。过程在进度卡，结论在聊天正文。  
> **当前决策**：写码主流程与过程加厚 **暂时冻结**，本报告作收口对照，不作为继续改码的排期单。

---

## 0. 一句话结论

| 维度 | 结论 |
| --- | --- |
| **写码结果同源** | 高：改盘手仍是 Cursor Local；落盘内容可与 IDE 同任务对齐 |
| **过程叙事相似度** | 中高：约 **7/10**（思考 + 工具穿插 + 过程助手话 + 终稿说明） |
| **工具行信息密度** | 中低：多有路径 / 部分编辑片段；**pattern / command / 结果摘录普遍偏薄** |
| **交互形态** | 故意不同：插件多澄清闸门 + HITL 确认卡；IDE 多为同线程连续对话 |
| **是否继续逼近** | **暂不加** pattern/command 等映射；主流程与过程输出冻结 |

## 1. 内容整体相似度

评分按「用户肉眼看一轮写码」的观感，不是像素级 UI 还原。  
**10 = 与 Cursor 原生 Agent 对话几乎同一观感**；**0 = 完全不像**。

### 1.1 总表

| 维度 | 相似度（约） | 说明 |
| --- | --- | --- |
| **A. 内容同源**（是否真是 Cursor 吐的，而非 DSH 模型复述过程） | **9/10** | 思考 / 工具 / assistant 来自 `@cursor/sdk` 流；结论取材自 Cursor 正文（优先末段 `## 说明方案`） |
| **B. 单轮过程叙事**（想 → 工具 → 中间说明 → 收口） | **7/10** | 进度卡已有交错时间线；前缀重复、双份说明方案等问题已明显收敛 |
| **C. 工具行细节**（Grep pattern、Shell 命令、Read/Grep 结果感） | **4/10** | 常见「工具名 + 路径」；编辑行可有短 `+/-` 片段；pattern/command/结果摘要几乎空 |
| **D. 终稿 / 结论可读性** | **8/10** | 聊天正文「本轮结论」结构清晰；与 IDE 终稿同属 Cursor 话术，但呈现通道拆成「卡内过程 + 正文结论」 |
| **E. 多轮续改体感** | **6.5/10** | 同 workspace 可续跑；仍须确认卡，不如 IDE 同线程一句话接着改顺 |
| **F. IDE 专属能力**（内嵌 Diff 面板、@文件、终端面板、引用块等） | **1～2/10** | 硬约束：只挂 DSH 聊天壳，不做第二 IDE |

**综合（在 DSH 壳内「像跟 Cursor 写码」）≈ 7/10。**  
剩余差距主要来自：**壳与门禁差异** + **SDK 流到达插件侧的工具参数偏瘦**，不是「没调 Cursor」。

### 1.2 相似度分层（避免误读）

```text
高相似（建议对外这样说）
  · 改了哪些文件、改得对不对 —— 认 Cursor + 同步账本
  · 过程里「在想 / 在读 / 在改」的节奏 —— 进度卡时间线
  · 收口说明方案的语义 —— 正文结论

中相似（别承诺「跟 IDE 一模一样」）
  · 每条工具的参数与结果丰满度
  · 续改摩擦（确认卡 vs 同线程追问）

低相似（产品刻意或壳限制）
  · 澄清 / HITL 确认步骤（企业门禁，IDE 默认没有）
  · Monaco Diff、@引用、侧栏、完整终端 UI
```

### 1.3 与「逼近上限」的关系

早期评估：在 DSH 壳内把 SDK 事件吃干，单轮观感上限大约 **6.5～7.5 成**。  
当前过程加厚后，**已落在该上限附近**。再抠工具行（pattern/command）经实跑核对：**官方键存在，但现网 `tool_call` 事件里常不带** → 加映射预期收益接近 0，故冻结停做。

## 2. 各重要节点对比

按冻结主流程四步 + 关键旁路节点对照。

### 2.1 节点总览

| # | 节点 | Cursor 原生 | 写码插件 | 相似判定 |
| --- | --- | --- | --- | --- |
| 1 | 需求澄清 | 通常直接开聊 / 模型自问 | DSH `ask_user_question`；入口级增删服务端硬拦 | **形态不同（产品门禁）** |
| 2 | 开工确认 | 一般无独立 HITL 卡 | 确认卡阻塞；确认前正文零输出 | **形态不同（安全底线）** |
| 3 | 思考（Thinking） | 可折叠思考块 | 进度卡可折叠思考流 | **高相似** |
| 4 | 工具调用行 | 参数细（path/pattern/command）、常有结果感 | 多路径；编辑可有 snippet；pattern/command/结果薄 | **中低相似** |
| 5 | 过程助手话 | 工具间短句说明 | 进度卡展示过程增量；过滤终稿段，避免与正文双份 | **中高相似** |
| 6 | 终稿 / 说明方案 | 同线程正文收口 | **进度卡不塞终稿**；聊天正文「本轮结论」 | **语义高相似、通道拆分** |
| 7 | 落盘 / 同步 | 直接改打开的工程 | 先沙箱 → 自动同步（scope / 敏感路径门禁） | **结果可对齐，路径不同** |
| 8 | 续改 | 同会话一句接着改 | 挂 parent Job；再走确认 → 进度 → 结论 | **能力有、摩擦更大** |
| 9 | 取消 | IDE Stop | 进行中可取消；已终态不得污染业务结果 | **语义对齐，实现分岔** |
| 10 | 状态文案 | IDE 自有状态 | RUNNING 等已中文化/规范化 | **可用，非像素对齐** |

---

### 2.2 节点 1 · 需求澄清

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **做什么** | 用户一句话开 Agent；模型可在对话里追问 | 新增/删除报表·页面·菜单等入口级诉求：**必须**先澄清 |
| **UI** | 聊天气泡 / 选项（视产品） | **只认** DSH 原生 `ask_user_question`；禁止插件自造澄清表单 |
| **差异原因** | IDE 面向个人开发者连续对话 | 企业场景防「范围没问清就开写」 |

**相似度**：流程故意不同，**不计入「逼近失败」**。

---

### 2.3 节点 2 · 确认开写（HITL）

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **做什么** | 发送即跑（或产品内建批准，非本插件模型） | 确认卡：「确认并用 Cursor 开写」；确认前不调 Cursor、正文空 |
| **差异原因** | 本地 IDE 信任当前用户 | 插件须 nonce / 防误触 / 防模型抢跑 |

**相似度**：形态不同；**确认后**才进入与原生可比的「Cursor 在干活」区段。

---

### 2.4 节点 3 · 思考流

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **来源** | Agent thinking 事件 | 同：SDK `thinking` → transcript |
| **呈现** | 可折叠 | 进度卡可折叠 |
| **观感** | 接近 | **高相似**（长度/折叠样式随壳略异） |

---

### 2.5 节点 4 · 工具调用（差距最大处）

| 子项 | Cursor 原生 | 写码插件（实跑） | 判定 |
| --- | --- | --- | --- |
| 工具种类可见 | Read / Grep / Shell / Edit / Glob / Todo… | 同（SDK 名映射展示） | ✅ |
| **路径** | 工程相对路径 | 多有；沙箱路径会 relativize | ✅ 大体可用 |
| **Grep pattern** | 常见 | Job 抽样 **几乎为 0** | ❌ 薄 |
| **Shell command** | 常见 | Job 抽样 **几乎为 0** | ❌ 薄 |
| **Read/Grep/Shell 结果摘要** | 常见 | 基本无；snippet 主要靠 **edit 沙箱 diff** | ❌ 薄 |
| **Edit 改动感** | Diff / hunk | 短 `+/-` snippet（有则显示） | △ 有但弱于 IDE |
| Todo 清单 | 勾选进度 | 可抽 Todo 摘要（有 args 时） | △ |

**根因备忘（已核对，非猜测）**

- SDK **类型**上：`args.pattern` / `args.command` / `result` 存在。  
- 插件 **抽取层**已认这些键。  
- 真人 Job：`path` 常有，`pattern`/`command` 计数为 0 → **现网流事件往往不带这些字段**（或截断为空）。  
- 决策：**不再补映射**；加了也难有观感收益。

---

### 2.6 节点 5 · 过程助手话（工具之间的短说明）

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **做什么** | 「先核对…」「接下来补前端…」穿插在工具间 | 进度卡展示过程 assistant；过滤终稿 / 说明方案段，避免与正文重复 |
| **曾有问题** | — | 前缀整段重复、双份 `## 说明方案` |
| **现状** | — | 去重与终稿过滤后叙事明显好转（用户体感约 7/10 的主因之一） |

**相似度**：**中高**。仍可能不如 IDE 每一次短句都完整、顺序完全一致（流合并与过滤策略所致）。

---

### 2.7 节点 6 · 终稿 / 本轮结论

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **位置** | 同一对话线程底部 | **聊天正文**「本轮结论」；进度卡**禁止**再塞终稿 |
| **内容** | 模型自然收口（常含方案说明） | 取材 Cursor assistant；优先末段 `## 说明方案`；begin/continue 终态强制出结论 |
| **同步账本** | 无（或 IDE 自有） | 可附已同步 / 待同步等执行信息 |

**相似度**：语义 **高**；呈现 **拆通道**（这是冻结口径，不是漏做）。

```text
原生：  [思考][工具][话][工具][话][终稿]     ← 全在一个面板
插件：  进度卡[思考][工具][过程话]  +  正文[本轮结论]  ← 有意拆开
```

---

### 2.8 节点 7 · 落盘与工程可见性

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **写哪里** | 当前打开工程 | 沙箱 → 受限同步回真工程 |
| **用户何时看见文件变** | 几乎即时 | 同步完成后；前端可刷新 |
| **范围外文件** | 视 Agent 权限 | `write_scope` / 敏感路径；不静默当成功 |

**相似度**：最终文件内容可对齐；**路径与门禁**不同，属编排层职责。

---

### 2.9 节点 8 · 续改

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **怎么开下一轮** | 同线程再发一句 | 同会话挂 `parent_job_id`；再确认 → 进度 → **必有**本轮结论 |
| **上下文** | IDE 会话记忆 | Job 摘要 + 沙箱复用 / 再拷 + Agent resume（可用时） |

**相似度**：**能力具备**，摩擦高于原生（多一次确认，符合冻结）。

---

### 2.10 节点 9 · 取消与终态

| | Cursor 原生 | 写码插件 |
| --- | --- | --- |
| **进行中取消** | Stop | 取消进行中 Job；推 SSE done |
| **已成功/失败** | 不再改写为「已取消」 | **禁止**对已终态再写 `cancelled=true` 污染账本；只封流 |
| **控制信号** | IDE 控件 | 只认权威字段（如 `error.code`）；**禁止**扫正文「取消」二字 |

**相似度**：业务语义对齐；实现按企业账本约束更严。

---

### 2.11 节点 10 · 状态与杂项文案

| 项 | 原生 | 插件 | 备注 |
| --- | --- | --- | --- |
| RUNNING / FINISHED 等 | IDE 文案 | 已做展示层中文化 / 规范化 | 细节可继续磨，非主流程 |
| 沙箱绝对路径 | 少见 | 已尽量相对化 | 偶发仍丑 |
| 复制进度 | IDE 复制 | 进度卡复制（含降级） | 可用 |

## 3. 对照示意（同一轮写码）

```text
【Cursor 原生】
用户：把员工工时报表加一列…
Agent：思考 → Grep{pattern,path} → 短说明 → Read → Edit(可见 hunk) → …
       → 同线程终稿说明

【写码插件 · 冻结形态】
用户：同上
DSH：澄清（若入口级）→ 确认卡
进度卡：思考 → 工具(名+路径[+编辑片段]) → 过程短说明 → …
正文：## 本轮结论（说明方案取材 + 同步信息）
```

**像的地方**：Cursor 真在改；节奏「想→动→说」在。  
**不像的地方**：工具参数/结果密度；多确认；结论不在卡内而在正文。

## 4. 差距归因（方便以后回看）

| 差距 | 主因 | 冻结期是否再动 |
| --- | --- | --- |
| 工具行偏瘦 | 现网 SDK `tool_call` 常无 pattern/command/result 可用载荷 | **不动**（已评估加映射无效） |
| 多一步确认 / 澄清 | 产品与安全冻结 | **不动** |
| 结论在正文不在卡内 | 主流程冻结 | **不动** |
| 无 IDE Diff / @引用 | DSH 壳边界 | **不做** |
| 过程叙事偶发毛刺 | 流合并 / 过滤边界 | 仅允许修明确 bug，不加厚功能 |

## 5. 对外说法建议

- ✅「在 DSH 里确认后，由 **Cursor** 在本机工程改码；进度卡跟手，正文有结论。」  
- ✅「过程观感接近 Cursor Agent，大约七成；工具细节和 IDE 面板仍有差距。」  
- ❌「进度卡输出 = Cursor IDE 对话框 1:1。」  
- ❌「再补几个字段就能和原生完全一样。」（现网缺键，补映射抬不动）
