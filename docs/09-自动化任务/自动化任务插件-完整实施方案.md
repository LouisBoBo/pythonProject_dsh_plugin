# 自动化任务插件：完整实施方案

> **状态**：方案定稿待开发（2026-09-17）  
> **落点**：本仓库独立 DSH Bundle `@zhongruan/dsh-automations`（目录建议 `dsh-automations/`）  
> **对照源**：腾讯 WorkBuddy Automations；`simplified-workbuddy` 功能 11（已落地的模板墙 + 调度 + 企微/飞书）  
> **交付形态**：公司插件市场安装；**零改** `DSH-ZR-WorkBuddy`  
> **产品一句话**：到点由插件自己叫醒一个**受约束的后台执行器**干活，结果进运行记录，可选推企微；人用**模板一键建**或**自定义指令**，也可在对话里用自然语言建任务。

---

## 0. 这是什么、不是什么

| 是 | 不是 |
|----|------|
| 闹钟到了，按已保存的指令跑一轮：查资料、读目录、写摘要、推群 | AI 自己决定改代码、自动 Git 提交、自动发版 |
| **模板任务**（预制 prompt + 日程 + 投递）+ **用户自定义任务** | 只做三套死模板、不允许改指令 |
| 独立插件进程内调度 + 独立运行账本 | 劫持当前 DSH 聊天、另造聊天会话树 |
| 与写码 / 审码 / 部署并行存在 | 替代功能 08～10（人确认卡那条线） |

工厂场景：每天早报进企微、周五出周报、巡检某目录有没有新文件。人配一次，系统自己跑。

## 1. 硬约束（不可协商）

对齐写码插件五条硬约束，再加自动化专属三条：

| # | 约束 | 本方案如何满足 |
| --- | --- | --- |
| 1 | **不动 WorkBuddy 任何功能** | 不改 `DSH-ZR-WorkBuddy`；不调引擎 `/api/cli`、不复用 `engine/app/automations`（那边尚未做完也互不依赖） |
| 2 | **simplified / 腾讯实现可复制语义** | 允许对照字段、RRULE、模板文案、调度算法、企微投递；**禁止**把 Deep Agents / Electron `AutomationMainService` 整包搬进插件 |
| 3 | **界面交给 DSH 原生壳** | 不写 Electron、不新开桌面窗。管理面 = 左侧栏 `sidebar.footer.action`「自动化」（与设置并列）打开主面板；对话面 = 工具摘要 |
| 4 | **独立插件、安装即可用** | `pack.sh` → `upload.sh` → 市场发现；本机填 LLM Key（自定义执行）与企微 Webhook 后可跑 |
| 5 | **执行器不进写码/提交/部署** | 安全前缀 + 工具白名单；`kind` 只认权威字段，禁止用正文正则猜「取消/部署」 |
| 6 | **聊天认 DSH，执行认本机 Run** | 运行记录是 L2 账本（类似写码 Job）；**禁止**为每次定时跑新建 DSH 会话树。见 [DSH会话与记忆分层](../架构与选型/DSH会话与记忆分层.md) |
| 7 | **人不在对话时也能跑** | 调度器挂在插件本机 HTTP 进程（宿主在、插件已加载）；不抢 DSH 当前 SSE |
| 8 | **契约字段权威** | 任务状态只认 `status` / `schedule_type` / `rrule` / `error.code`；Run 终态 `succeeded` / `failed` / `skipped` / `cancelled` 不可再改写业务结果 |

## 2. 对照：腾讯 WorkBuddy × simplified × 本插件

### 2.1 腾讯 WorkBuddy（产品机制，必须对齐）

来源：`simplified-workbuddy/docs/自动化任务/WorkBuddy自动化任务学习笔记.md`（对照完整版客户端 `~/.workbuddy/workbuddy.db` + `workbuddy-server/src/automation/`）。

```text
对话里自然语言
  → Agent 调 automation_update（create/update/view/delete）
  → 写入 automations（prompt 只写任务内容；时间进 rrule / scheduled_at）
        ↓
Electron 主进程 SchedulerEngine 每 30s tick
  → ACTIVE 且 next_run_at ≤ now → 后台会话执行 prompt（CodeBuddy CLI）
  → automation_runs 收件箱 + 可选微信/企微 outbox
```

| 腾讯能力 | 本插件是否做 | 说明 |
|----------|--------------|------|
| 循环 `recurring` + RRULE | **P0** | `FREQ=DAILY/WEEKLY` + `BYHOUR/BYMINUTE/BYDAY` |
| 单次 `once` + `scheduled_at` | **P0** | 跑完自动 `paused` |
| `valid_from` / `valid_until` | **P1** | 生效窗口 |
| 对话 `automation_update` 建任务 | **P1** | 工具名 `zr_auto_update`，禁止模型直接改 JSON 文件 |
| `cwds` 工作目录 | **P0** | 单 cwd 即可；多 cwd 并行 P2 |
| 30s tick 调度 | **P0** | 插件进程内，默认 30s，`AUTOMATIONS_TICK_SEC` 可调 |
| 后台独立执行、不搅当前聊天 | **P0** | 插件自有 executor，**不**占用 DSH 流式锁 |
| 运行记录 / 收件箱 | **P0** | `runs.json` + 面板「运行记录」 |
| 企微/微信推送 | **P0 企微群机器人** | 应用消息 / 微信个人号 = P2 |
| 休眠错过补跑、排队、多用户 owner | **P2** | 先记录 `skipped=host_down`，不做 24h jitter 补跑 |
| 指定模型 / skills / connector | **不做（本阶段）** | 执行器用插件配置的 LLM + 固定白名单工具 |

### 2.2 simplified-workbuddy（已落地，UI 与模板必须对齐）

来源：`docs/功能实现/11-自动化任务.md`、`apps/web/src/automationTemplates.js`、`data/automations/*.json`。

| simplified 能力 | 本插件 | 差异 |
|-----------------|--------|------|
| 侧栏页：定时任务 + 运行记录 | 左侧栏「自动化」主面板 | 与设置并列，对标 `/automations` |
| 三套模板墙 | **P0 同样三套 + 目录巡检** | 文案可公司化，结构不变 |
| 编辑弹窗：名称 / 指令 / 循环或单次 / 企微 / 飞书 | **P0 到企微**；飞书表 P1 | 弹窗做在面板内 |
| 自定义才显示「AI 改写」 | **P1** | 模板实例不改写 prompt 骨架，除非用户切成自定义 |
| Deep Agents 当执行器 | **禁止照搬** | 模板走专用流水线；自定义走插件内约束 Agent |
| 与对话抢同一把 stream lock | **不抢** | 插件进程独立跑；用户聊天不被 skip |
| 飞书多维表格 append | **P1** | P0 只保证运行记录 + 企微 |
| 安全前缀禁止写码/提交/部署 | **P0 原样保留语义** | 白名单工具，比前缀更硬 |

### 2.3 和「WorkBuddy 引擎 P0-4」的关系

`DSH-ZR-WorkBuddy` 文档曾定：「自动化 P0 = 固定模板 + 企微，**不做任意自然语言定时 Agent**」。

**本插件产品口径不同**：用户明确要求 **模板 + 用户自定义**，对齐腾讯。因此：

- 模板：固定流水线（更稳、可验收）
- 自定义：允许自然语言指令，但执行面是**插件内约束 Agent**（工具白名单），不是「后台完整 CodeBuddy / 写码车道」
- 与引擎 P0-4 **并存、互不调用**；以后若引擎也做自动化，任务库不共用

## 3. 目标体验

### 3.1 两条创建路径（都要有）

```text
路径 A · 模板（主路径，对标 simplified 空态墙）
  打开「自动化」面板 → 点模板卡片 → 预填名称/指令/时间/是否推企微
  → 可改时间与推送 → 保存 → 「立即执行」验收

路径 B · 自定义（对标腾讯 + simplified 弹窗）
  「+ 添加自动化」→ 填名称 + 执行指令（可 AI 改写）
  → 选循环/单次与时间 → 可选 cwd、企微 → 保存 → 立即执行

路径 C · 对话（对标腾讯，P1）
  「每天早上 8:30 看一下 /data/delivery 有没有新文件，汇总发企微」
  → 模型调 zr_auto_update → 聊天里出现任务卡（可保存/立即测试）
```

### 3.2 到点之后人看到什么

1. 宿主保持打开（WorkBuddy / `dsh web` 在跑，插件已加载）。  
2. 到点后**当前对话不被打断**。  
3. 面板「运行记录」出现一条：进行中 → 成功/失败；摘要可点开。  
4. 若勾了企微且系统配置已开：群里出现整理后的 Markdown。  
5. 单次任务跑完自动暂停；循环任务写入 `next_run_at`。

### 3.3 空态文案（沿用 simplified）

- 标题：开启你的第一个自动化任务吧  
- 模板区标题：自动化任务模板  
- 能力说明：**适合** MES 简报 / 联网摘要 / 目录与 git **只读**汇总；**不适合**改代码、提交、部署。

## 4. 架构

```text
┌─────────────────────────────────────────────────────────────────┐
│  DSH 原生壳（Web 聊天 · 不新写）                                  │
│  · sidebar.footer.action「自动化」：与设置并列，打开主面板         │
│  · 主面板：模板墙 / 任务列表 / 运行记录 / 编辑 / 推送配置          │
│  · tool.call.toolview：对话建任务卡、立即执行结果卡                │
└──────────────────────────────┬──────────────────────────────────┘
                               │ 127.0.0.1 插件 HTTP
┌──────────────────────────────▼──────────────────────────────────┐
│  Bundle @zhongruan/dsh-automations                               │
│  · 工具：zr_auto_list / zr_auto_update / zr_auto_run / …         │
│  · Scheduler：30s tick，只认 status=active + next_run_at         │
│  · Executor：模板流水线 ‖ 自定义约束 Agent                        │
│  · Store：automations.json / runs.json / runtime.json            │
│  · Delivery：企微 webhook（P0） / 飞书表（P1）                    │
└─────────────┬─────────────────────────────┬─────────────────────┘
              │                             │
     模板专用能力                    自定义白名单工具
     （search / git digest /        read_file · list_dir
      MES HTTP 可选）                web_search · 知识库可选
                                    ❌ write / bash / git commit
                                    ❌ cursor-coding / deploy
```

### 4.1 为什么执行器不能复用当前 DSH Agent

| 若复用当前对话 Agent | 后果 |
|----------------------|------|
| 到点把 prompt 塞进正在聊的 session | 搅乱用户上下文，违反腾讯「后台会话」 |
| 另开 DSH session 当定时跑 | 插件另造会话树，违反会话分层定稿 |
| 抢 DSH SSE 锁 | simplified 已证明：人一聊天，任务就被 `stream_busy` 跳过 |

因此：**定时执行 = 插件进程内 L2 Run**，与写码 Job 同层思想。对话只负责「建/改/查/立即跑」这些同步工具调用。

### 4.2 本机 HTTP 职责

先例：`dsh-cursor-coding`、`dsh-remote-review`。插件 `apply()` 启动 `127.0.0.1` 服务（建议默认端口 **18789**，避开写码 18788、审码 18787）。

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/health` | 调度是否在跑、下次最近任务、版本 |
| GET/POST/PATCH/DELETE | `/api/automations` | 任务 CRUD |
| GET | `/api/automations/runs` | 运行记录分页 |
| POST | `/api/automations/:id/run` | 立即执行 |
| POST | `/api/automations/:id/cancel` | 取消**进行中**的 Run（终态禁止改业务字段） |
| POST | `/api/automations/rewrite-prompt` | AI 改写（仅自定义） |
| GET/PUT | `/api/settings` | 调度开关、LLM、企微（密钥脱敏回读） |

面板只打这个本机口，不经过 WorkBuddy 引擎。

## 5. 数据模型

存储目录（建议）：`~/.dsh/automations/`（或 profile 下 `data/automations/`），**原子写**（`.tmp` + `rename`），对齐 simplified `store._write_json_atomic`。

不共用 `~/.workbuddy/workbuddy.db`。

### 5.1 `automations.json`（任务定义）

字段对齐腾讯表 + simplified JSON：

| 字段 | 类型 | 权威含义 |
|------|------|----------|
| `id` | string | `auto-` + hex，主键 |
| `name` | string | 展示名，≤120 |
| `prompt` | string | **仅任务内容**，不含「每天 9 点」、不含目录路径 |
| `source` | `template` \| `custom` | 创建来源；模板实例仍可改日程，改 prompt 后保持 template_id 仅作溯源 |
| `template_id` | string \| null | 如 `daily-ai-news`；自定义为 null |
| `status` | `active` \| `paused` | 只认这两个；删除走 `deleted_at` 或物理删定义、**保留 runs** |
| `schedule_type` | `recurring` \| `once` | |
| `rrule` | string | 循环规则 |
| `scheduled_at` | string \| null | 单次 ISO 本地时间 `YYYY-MM-DDTHH:mm` |
| `valid_from` / `valid_until` | string \| null | P1 |
| `cwds` | string[] | 规范化绝对路径；必须落在用户声明的根下 |
| `push_to_wecom` | boolean | 任务级开关；与全局 `WECOM_PUSH_ENABLED` 与 |
| `bitable_sync` | object \| null | P1 |
| `next_run_at` / `last_run_at` | number \| null | Unix 秒 |
| `created_at` / `updated_at` | number | Unix 秒 |

**禁止**：把调度写进 `prompt`；用 `name` 正则判断任务种类（模板种类只认 `template_id`）。

### 5.2 `runs.json`（运行账本）

| 字段 | 含义 |
|------|------|
| `id` | `run-` + hex |
| `automation_id` / `automation_name` | 冗余快照，删任务后记录仍可读 |
| `status` | `running` → `succeeded` \| `failed` \| `skipped` \| `cancelled` |
| `skip_reason` | 仅 skipped：`already_running` / `scheduler_disabled` / `host_stopping` |
| `summary` | 给人看的摘要（截断上限约 16KB） |
| `error` | `{ code, message }`；取消只认 `cancelled` \| `interrupted` \| `aborted` |
| `started_at` / `finished_at` | Unix 秒 |
| `delivery_status` | `pending` \| `sent` \| `failed` \| `skipped` \| `dry_run` |
| `bitable_status` | P1 |

终态（succeeded/failed/cancelled）**禁止**再 patch 成另一种业务结果；取消进行中的 Run 只改 `status=cancelled` + `error.code`。

### 5.3 `runtime.json`（互斥）

同 `automation_id` 同时只允许一个 `running`。`mark_running` / `clear_running` 必须成对；进程启动时把残留 `running` 收口为 `failed`（`error.code=interrupted`），与写码插件孤儿 Job 回收同思路。

## 6. 模板任务

### 6.1 模板是「创建向导」，不是只读死任务

点模板 = `create_automation` 时带上预制 `prompt` / `rrule` / `push_to_wecom` / `template_id`。保存后它就是普通任务，可暂停、改时间、立即执行。  
**不要**做「系统内置、用户不能删」的幽灵任务——腾讯也没有。

### 6.2 P0 模板清单

对齐 `automationTemplates.js`，并补一条腾讯最常见的目录巡检：

| `template_id` | 标题 | 默认日程 | 默认企微 | 执行器 |
|---------------|------|----------|----------|--------|
| `daily-ai-news` | 每日 PCB+AI 新闻推送 | 每天 09:00 | 开 | **新闻流水线**：检索 → 3～5 条中文摘要（标题/要点/链接） |
| `weekly-work-report` | 每周工作周报 | 每周五 17:00 | 关 | **git 只读 digest** + LLM 按固定大纲归纳；无提交则写「本周暂无新提交」 |
| `mes-daily-production-report` | 每日生产运营日报 | 每天 08:00 | 开 | **MES HTTP 流水线**（见 6.3）；未配置 MES 则创建时提示、立即执行失败码 `mes_unconfigured` |
| `dir-watch-digest` | 目录变更巡检 | 工作日 09:00 | 开 | **只读 list/mtime**，汇总新文件；无变更输出「无新文件」 |

新闻 / 周报 / 生产日报的 **prompt 正文**以 simplified 现网文案为母本，公司化时只改专名（ZR WorkBuddy → 当前工作区），不改输出骨架。

### 6.3 模板执行器：专用流水线，不走「通用 Agent」

simplified 用任务名关键字拼 prefix（`_is_weekly_work_report` 扫 name/prompt）——**本插件禁止这套启发式**。只认 `template_id`。

```text
execute_run(automation)
  if automation.template_id in TEMPLATE_PIPELINE:
       pipeline[template_id](ctx)     # 确定性步骤 + 必要时 LLM 润色
  else:
       custom_agent(ctx)              # 白名单工具
```

| 模板 | 确定性输入 | LLM 角色 |
|------|------------|----------|
| 新闻 | web 检索原始条目（可先接现有搜索 API / 可配置源） | 只整理，禁止编造链接 |
| 周报 | `repo_digest`：`git log` / `git status` **只读** | 按「已完成 / 进行中 / 下周」排版 |
| 生产日报 | MES `query` 返回的真实 JSON | 按早报 5 段排版；无数据的段整段省略 |
| 目录巡检 | `fs.readdir` + mtime 窗口（上次 `last_run_at`～现在） | 可选；无文件则固定句，不必调模型 |

MES 依赖：设置项 `MES_BASE_URL` + 既有查询协议（可复用 simplified `query_tool` 的 HTTP 形态，**拷贝协议不拷 Deep Agents**）。没有 MES 的客户：模板卡片上标注「需配置 MES」，允许保存但立即执行给出明确失败。

### 6.4 日程预设（弹窗与模板共用）

直接复用 simplified `AUTOMATION_SCHEDULE_PRESETS`：

- 每天 08:00 / 08:30 / 09:00 / 18:00  
- 每周五 17:00、每周日 10:00  
- 工作日 09:00  
- 「自定义」：每天 / 工作日 / 每周(多选星期) + 时分 → 生成 RRULE  

P0 **不做** `FREQ=HOURLY`、`FREQ=MONTHLY`（腾讯有，ZR 可后补）。

## 7. 用户自定义任务

### 7.1 什么叫「自定义」

`source=custom` 且 `template_id=null`。用户自己写 `prompt`（目标 / 步骤 / 输出 / 禁止），调度与投递与模板任务同一套字段。

适合：巡检指定目录、整理某类新闻、把只读查询结果写成固定格式。  
不适合：改仓库、提交、部署、给外部系统写操作（除非将来单独开 HITL，本阶段不做）。

### 7.2 指令骨架（保存前建议填入，AI 改写也按此）

```text
【目标】…
【数据来源】…（必须真实查询/读取，禁止编造）
【步骤】…
【输出格式】…
【禁止】写码、改文件、Git 提交、部署、泄露密钥
```

`prompt_rewrite`（P1）：只扩写表述，**禁止**改日程、禁止加入企微/飞书密钥、禁止改写成写码任务。系统提示与 simplified `prompt_rewrite.py` 对齐。

### 7.3 自定义执行器（约束 Agent）

插件内最小 Agent 环（非 DSH 会话）：

1. 拼 **安全前缀**（禁止写码/提交/部署/删除用户文件）。  
2. 注入 `cwd`、当前日期、`last_run_at`。  
3. 循环：LLM function-call ↔ **白名单工具**，步数上限（建议 8）、总超时（建议 120s）。  
4. 最终 assistant 文本写入 `summary`。  
5. 成功后再走投递。

**P0 白名单**

| 工具 | 作用 | 守卫 |
|------|------|------|
| `list_dir` | 列目录 | 路径必须在 `cwds` 内 |
| `read_file` | 读文本 | 后缀白名单、单文件大小上限 |
| `web_search` | 检索 | 次数上限；无则任务失败码 `tool_unavailable` |

**P1 可选接入（探测到再注册，未装则工具不出现）**

- 知识库检索：HTTP 调已安装的 `@zhongruan/dsh-knowledge`（失败降级，不把知识库插件当硬依赖）  
- MES `query`：仅当设置了 `MES_BASE_URL`

**永远不注册**：Write、Bash、Git commit/push、`zr_cursor_*`、审码、部署、任意 `rm`。

### 7.4 与模板的切换

用户从模板创建后大改 `prompt`：**仍保留 `template_id` 作溯源**，但执行走哪条路只认「该 `template_id` 是否仍在 `TEMPLATE_PIPELINE` 且用户未勾选『按自定义指令执行』」。

更干净的 P0 规则（推荐，条件宁窄）：

- 有 `template_id` 且未改默认 prompt 哈希 → 走模板流水线  
- 否则走自定义 Agent  

prompt 哈希在 create 时写入 `prompt_fingerprint`；编辑 prompt 后指纹变化即走自定义。**不要**扫正文里有没有「新闻|周报」。

## 8. 调度与执行

### 8.1 调度器

对齐腾讯 `RUN_TICK_MS = 30000` 与 simplified `scheduler.py`：

```text
插件 HTTP listen 成功
  → 若 settings.scheduler_enabled
  → 先 sleep 2s，再每 tick_sec（默认 30，最小 5）
       list automations
       缺 next_run_at 则 enrich
       should_run_now → execute（await，同 tick 串行）
```

`should_run_now`（只认字段）：

- `status === active`
- `next_run_at` 存在且 `<= now`
- `last_run_at` 未盖住本轮 `next_run_at`（防重复）
- 未在 `runtime` 中 running
- P1：落在 `valid_from`～`valid_until`

全局关调度：`scheduler_enabled=false` 不建 loop；已 running 的本轮允许跑完。

宿主退出：`clear_running`；来不及的标 `interrupted`，**不**在下次启动偷偷补跑（P0）。P2 再做 missed recovery。

### 8.2 `execute` 编排（对标 simplified executor，去掉 Deep Agents）

```text
mark_running(automation_id)
append_run(status=running)
try:
    按 §7.4 选模板流水线或自定义 Agent
    update_run(succeeded, summary)
    deliver_wecom（失败只写 delivery_*，不改 status）
    P1: sync_bitable
finally:
    clear_running
推进 last_run_at / next_run_at；once → status=paused, next_run_at=null
```

立即执行 `POST .../run` 与闹钟走**同一** `execute`。正在 running → 返回 `skipped=already_running`，HTTP 409，不新建第二条 running。

### 8.3 并发

| 规则 | P0 |
|------|----|
| 同任务 | 互斥 |
| 不同任务 | tick 内串行（先到期先跑） |
| 与用户 DSH 聊天 | **并行**，互不影响 |
| 全局 | `max_concurrent=1` 足够 |

## 9. 对话工具（DSH Agent 可调）

安装后 `ctx.tools.register`。description 写清「用户说每天/每周/定时/提醒就调我」，对标腾讯「即使用户没说自动化也应建任务」。

## 11. 投递

原则与 simplified 相同：**先落盘 Run，再旁路投递**；投递失败不把业务 `status` 改成 failed；密钥不进 prompt、不进 `automations.json`。

### 11.1 企微群机器人（P0）

```text
POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...
content-type: markdown，单条 ≤ 4096 字节
```

任务 `push_to_wecom` × 全局开关 × 非 dry_run 才真正 HTTP。  
新闻/早报用 `format_wecom_push` 拆段控字节（可拷贝 simplified `run_summary_text.py` 语义到 TS）。

短失败重试 1 次。`delivery_status` 写入该 Run。

### 11.2 飞书多维表格（P1）

对齐 `bitable_sync`：Agent/流水线在摘要中输出约定 JSON 围栏 → 解析 → append。P0 不做，避免和审码插件的飞书文档凭证搅在一起；若做，设置分组独立（`FEISHU_BITABLE_*`）。

## 14. 安全与状态机自检

对照仓库写码约束，自动化侧必须过：

- [ ] 控制流只认 `status` / `schedule_type` / `rrule` / `error.code` / `template_id`，不扫用户可见正文做取消或「这是周报」  
- [ ] succeeded/failed Run 不再写 `cancelled=true`、不改 `summary` 业务结论  
- [ ] 新任务、恢复 active、立即执行前：该 id 的 `cancelOnce` 类标志（若有）清零  
- [ ] 成功日报不会因为摘要里出现「取消」二字被打成已取消  
- [ ] `cwds` 规范化后不得逃出允许根  
- [ ] Webhook / LLM Key 不进 prompt、不进 runs.summary  
- [ ] 调度关闭或任务 paused → 到点不跑

## 15. 验收清单（P0）

1. 市场或本地安装后，左侧栏「自动化」能保存 Key / 企微；`/health` 显示 scheduler=on。  
2. 空态看到模板墙；点「每日 PCB+AI 新闻」保存为 active。  
3. **立即执行** → 运行记录有摘要；再开企微干跑 → `delivery_status=dry_run`。  
4. 自定义任务：名称+指令+每天 18:00 保存；列表显示「每天 18:00」；暂停后到点不跑；恢复后 `next_run_at` 为未来时刻。  
5. 进行中再点立即执行 → 409 / already_running，**不**出现两条 running。  
6. 用户同时在 DSH 里正常聊天写码 → 自动化仍能跑完（不出现 simplified 的 stream_busy）。  
7. 任务指令里写「提交代码并部署」→ 执行器拒绝高风险工具，Run `failed` 且 `error.code=forbidden_action`，仓库无 commit。  
8. 删除任务定义后，历史 runs 仍在。  
9. 重启宿主：残留 running 收口为 interrupted；循环任务按新的 `next_run_at` 等下一轮，不连开两次。

## 18. 建议的第一期接口（中文文档，实现时写进 OpenAPI 注释）

## 19. 决策摘要（开发前默认按此，改口径需书面）

1. **独立 DSH 插件**，不是引擎 feature。  
2. **模板 + 自定义**都做；模板走专用流水线，自定义走白名单 Agent。  
3. **对齐腾讯**：RRULE / once、prompt 与日程分离、30s 调度、后台执行、运行记录、企微、P1 对话建任务。  
4. **对齐 simplified**：模板墙、编辑弹窗、立即执行、先落盘再投递、禁止写码提交部署。  
5. **收窄腾讯**：后台不是完整 IDE Agent；无休眠补跑（P0）；无多用户 owner。  
6. **UI**：左侧栏「自动化」主面板为主，对话工具为辅。

确认本方案后，下一动作是在仓库创建 `dsh-automations/` 按 P0 开工（store → schedule → 面板 CRUD → 一条新闻模板跑通 → 企微干跑）。
